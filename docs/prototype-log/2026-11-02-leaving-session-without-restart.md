# 2026-11-02 Leaving a session without a restart (tested by me)

S1 to S4 of [sessions.md](../sessions.md), after the build, the tests, clippy and the offline checks against `eu4.exe` passed; two defects found in the run were fixed and the build installed again between runs. `eu4.exe` was started directly five times, with the playset as installed (the Chinese one) and the regional-combat extension loaded, and driven by `eu4-harmony game` and `tools/game-input.ps1`. Backups as AGENTS.md says, with the framework files installed in the game folder copied aside first. The player's save manager, EU4SaveMaster.exe, ran throughout.

- **An in-game load from remote control**: `menu.load autosave` (the Ethiopian autosave of 1445.1.1, 36 MB of plain text) from a game of England: "session ending (reason 1)", the game's load, the new session answered after 7.4 s. Into an ironman save from a plain game: 8.1 s, nothing saved first.
- **The first in-process return**: `menu.return` answered `main_menu` after 1.2 s, from the same process. Three things were left: the map manager's minimap, on the main menu's corner; the session's armies and fleets, drawn on the main menu's map; and no continue box. The minimap is now let go before the switch, and the session taken down by the in-game load's world reset, which leaves the history unread. After that, a return from an ironman game of England took 2.8 s (its ironman exit save 0.5 s, the reset 1.9 s), and the main menu looked as after a start: no minimap, no units, the continue box offering England 1448.3.1, the save just written. Why the continue box was missing before was not looked into.
- **From the returned main menu**: loading a save first read the history as the single player setup was entered (2.9 to 4.3 s), then loaded it, 6.3 to 9 s in all. `menu.start FRA` was refused at first, "FRA has no land at the start date": the world had no history yet. Fixed: until the setup is entered the land is not looked at. Then 8.4 s.
- **A new game from a session**: `menu.start FRA` from a game answered at once with the session it was leaving; the game did start as France 8 s later. Fixed: a start not yet run waits. From Castile's ironman game, `menu.start TUR` then took 14.6 s: the ironman exit save, the return, the history, the start; answered with the new game.
- **Ironman**: from Castile's ironman game, `menu.load England-1` wrote Castile's ironman exit save (the file rewritten), then loaded. The save the game makes as it sets up a loaded ironman session then failed: "备份文件失败", and `error.log` "Failed to rename save games/Castilla-5.eu4 … Back up failed", "tried to modify a file the OS needs", a `.tmp` left; the load still held the file (research/main-menu.md). Fixed: that save is made once the load has returned. Then `England-1.eu4` was rewritten with nothing in `error.log`.
- **Undo**: with "save an ironman game before an in-game load" turned off in the settings window, Castile's ironman game was run 10 days to 1470.3.23 and `Castilla-5` loaded again in the game: the file was left as it was, and the session was at 1470.3.13.
- **The player's way**: in an ironman game the in-game menu's load button was on; the load window listed the saves; the question read "读取存档 英格兰1444_11_11？当前的铁人游戏会先保存。" with the setting on, and the game's own "你确定读取游戏存档 英格兰1444_11_11 并中止当前游戏？" with it off. Accepted, the load took the framework's steps.
- **The settings window**: the three toggles showed, on; switching one and saving wrote `save_ironman_before_load=no` and took effect at once; the old `text_appearance` line was dropped.
- **20 rounds** of a return, a load from the main menu, an in-game load and a new game from a session: 80 answers, all right, no crash. Handles stayed between 1043 and 1064. Private bytes grew from 4,094 to 4,825 MB, about 30 MB a round. Then, in the same process, 20 of the game's own in-game loads grew it by 98 MB (5 MB each), and 10 returns each followed by a load from the main menu by 107 MB (11 MB each, two world resets).
- **Against a new process**: France started after a return, and in two new processes, read through `country.get` (20 countries), `province.get` (13 provinces) and `army.list`. The provinces and armies were the same in all three; the countries' treasury, prestige and rivals differed between the two new processes too (chosen at random at the start). After the return, Poland's max manpower was 26,430 against 26,305 in both new processes (manpower 8,632 against 8,631): something the resets leave behind, not looked into yet.
- **Not seen in the running game**: returning with one of the game's windows open, during an autosave, while observing, or from the end-of-game summary; an extension's `on_session_ended` (the regional-combat extension does not implement it; the core logged "session ending" each time); `menu.return` with "return without restarting" off; a failing ironman exit save; cloud saves; the still notice, which is not built.
- **Cleanup**: the game was closed by ending its process each time. `tools/player-state.ps1 -Restore` listed what the runs changed (the framework's logs and settings, `pdx_login_cache.txt`, `settings.txt`, `shortcuts.txt`, `Castilla-5.eu4` and its backup, `England-1.eu4`, and `England-1_Backup.eu4` added), put each back, removed the added file and found every file as the backup had it. No crash folder was made. The three framework files in the game folder were put back and compared equal to the copies. The scripts, copies and screenshots of the run were deleted.
