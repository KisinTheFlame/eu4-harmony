# 2026-11-08 What a frame's drawing reads (tested by me)

Whether a frame's drawing could run on a thread of its own while the next day runs ([research/drawing-beside-the-day.md](../research/drawing-beside-the-day.md), "The drawing on a thread of its own while the next day runs"). The developer build with the write watch alone, at `a0f26d4` with the watch's `reads-before` and `after-days` of this branch; `dev.toml` watched the map's drawing `0x10a59a0` and the GUI's `0x14dd010` and `0x14dd540` for their reads, then the daily tick's execute `0xb79520` for its writes, two rounds, after 20 game days. One claim of the whole game (before test games), about 20 minutes, the game started hidden; the 1780.7.1 save copied in and loaded with `menu.load`, `console run observe`, `session.view TUR`, `time.advance 60` at speed 5, "Faster time" on.

- **The watch began** after 20 days, at 1780.7.21. **The map's drawing** was watched in 23 s: 97 other threads held, 8,280,560 heap blocks, 2,190 MB of pages inaccessible, set up in 1.6 s; 3,065,935 reads and writes. It read 8,481 blocks and 263 places of `eu4.exe`'s data, most of them `d3d9.dll`'s and the driver's; the game's code read the map manager's per-province arrays, the world's province array and each of the 4,942 provinces' `+0x18` and `+0x20`, copying the byte at `+0x18` into the map manager's byte for the province.
- **The GUI's drawing** stopped the game at its start: the main thread in a wait (`UserRequest`), 96 threads held, no CPU used, the log unwritten from then on. `cargo xtask profile` could not read the process's modules (their list is in the heap, then inaccessible). The game was ended by the release after 16 minutes. The day's writes were not reached.
- **Not verified**: what the main thread waited on (no debugger was at hand); the GUI's drawing's reads; the day's writes to what the map's drawing read; what a province's `+0x18` is; a frame other than this one.
- **Cleanup**: the release put back the player's files, removing the copied save, and the game folder's framework files, and said the game did not crash; `dev.toml` removed; the log kept in the scratchpad and deleted after.
