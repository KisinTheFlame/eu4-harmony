# 2026-11-03 Why deleting the sets of modifiers corrupts the heap (tested by me)

Experiment builds, not committed, on master after the day's repairs were merged (research/main-menu.md, "The 0x178 objects"). Where the repair taken out deleted a set, they kept it instead, with a copy of its bytes; a thread compared the kept sets with their copies every three seconds, and a free of a kept set was logged with the game's return addresses on the stack. Five processes under the game lock, which backed up and restored the player's files; the framework files in the game folder copied aside first. `eu4.exe` started directly, the playset as installed, driven by `eu4-harmony game`, rounds as in the acceptance: a load of `法兰西1495_11_19` from the main menu, 30 days at speed 5, an in-game load of `英格兰1444_11_11`, 10 days, a return, a new game as France, 10 days and a return.

- **Kept, three rounds**: 13,079 sets kept; none changed after it was kept, none was freed by the game, none was left by two modifiers.
- **Kept, then deleted at the next world reset**, twenty rounds: each reset deleted the 574 to 2,270 sets kept since the last. At the seventeenth round the game ended a second after a reset of an in-game load had deleted 590 of them, its heap corrupted (`0xc0000374`). Windows kept a dump: the main thread was in the load, in the modifiers it works out after reading the save (`0x9f9500`), copying a set (`0x329ee0`) and allocating a string of 0x20 bytes, in the same size of block as a `shared_ptr`'s control block (0x18) or a vector of one `shared_ptr`.
- **Kept, with the blocks they hold watched**, three rounds: the buffer of `shared_ptr`s of each of 13,630 kept sets and every control block in it, 20,330 blocks: the game freed none of them. The `shared_ptr`s count atomically (`lock xadd`, `0x94230`, `0x8ea610`).
- **Kept, with the census on**, two and three rounds: at each world reset every live block the census knows was searched for the kept sets' addresses, 3 to 5 seconds each time. 19 to 227 pointers to 1 to 3 per cent of the kept sets were found, to sets kept at that reset and to sets kept up to eight resets before alike. Most were in bytes the game does not use, such as what follows a short string's end in `std::string`s a set's copy copies (`0x1ee2a0`, at `+8` of blocks of 0x20 bytes): the search cannot tell those from pointers, and found no holder that stands out.
- **Not found**: what reads or writes a deleted set, or what it reaches through one. Each set keeps raw pointers to the sets added to it (`0x8ea420`, its vector at `+0x38`), which a copy of a set copies (`0x8ea2d0`), and the game never deletes a set it made for a country's modifiers; whatever copied one of their containers may point to a set after the world reset.
- **Cleanup**: each game was closed by ending its process; the dump was deleted. The three framework files in the game folder were put back and compared equal to the copies taken before. Releasing the game restored the player's files and found every file as the backup had it.
