# 2026-10-31 Extension save data in the save the game makes while loading an ironman game (tested by me)

The defect the run of 2026-10-30 found: the save the game makes while loading an ironman game wrote no extension save data, so a crash before the next save lost it. The loader's observer now makes the loaded data current as soon as the load has replaced the world, not at the session's first safe frame. The build was that change on master at `Let the player choose the weight of the text font and the map font (#12)`, after the build, the tests and the offline checks against `eu4.exe` passed. The regional-combat extension was rebuilt from its repository's master against this SDK, in a copy of the repository (its 16 tests pass), and its DLL replaced the mod's for the run. `eu4.exe` was started directly, three times. Backups as AGENTS.md says, with the framework files installed in the game folder and the mod's DLL copied aside. The game was driven by `eu4-harmony game` alone.

- **Startup**: 579 dependency points match; 106 hooks, 4 writes; the extension loaded.
- **The save**: a copy of the ironman save `Castilla-5` as `rc-ironman-test` (Castile, 1470.3.13), loaded once ("data for 0 extension(s)"; the game rewrote the file) and the game ended. Extension save data for the file as it then was was written by hand, as the framework writes it: the file's digest, path and size, the date as the game counts it (56678904), and a task turned on with radius 8 for the army in Constantinople (`28136330756150`, 14 regiments). So no army had to be selected with clicks; the framework writing such a file itself was seen on 2026-10-30.
- **Loading**: "loaded … with data for 1 extension(s)", 4.4 s later "saves: wrote extension data for …rc-ironman-test.eu4" under the digest the file had after the load, with the same task, and 0.14 s after that "session 2 started (from a loaded save: true)" and the extension's "restored 1 task(s)". The order is the one the change relies on: the game's save comes after its loader returns and before the session's first safe frame.
- **After a crash**: the game was then ended at once, as a crash would end it, the save unchanged. Started again and loaded, it gave "data for 1 extension(s)", the save made while loading wrote the data again, and "restored 1 task(s)", the army still in 151.
- **Not seen in the running game**: a normal save or a new game with the change (neither is saved while loading; a unit test covers a load that does not replace the world leaving the data alone); a load whose save could not be identified; the radius box on the restored task.
- **Cleanup**: each game was closed by ending its process; no crash folder was made. `player-state.ps1 -Restore` listed what the run changed (the test save and its `_Backup`, three extension save data files, the framework's logs, `pdx_login_cache.txt`, `settings.txt`, `shortcuts.txt`), put each back and found every file as the backup had it. The framework files and the mod's DLL were put back and compared equal to their copies; the regional-combat repository has no change. The copy of the repository, its build and the backups were deleted.
