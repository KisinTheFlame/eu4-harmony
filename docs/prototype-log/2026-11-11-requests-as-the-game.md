# 2026-11-11 Requests as the player and as the game (tested by me)

Part M9 of [mod-capabilities.md](../plans/mod-capabilities.md): each remote control request acts as the player unless it asks to act as the game ([ADR requests-act-as-the-player-or-as-the-game](../adr/2026-11-11-requests-act-as-the-player-or-as-the-game.md)), on a branch from `d7cc5d25` (M1) with the change not yet committed. The build had the test games' pipes. One test game of this checkout's, started hidden, with the player's playset (the Chinese one); before it started, its framework settings file was given `remote_full_view=yes`, the setting this part removes, as a player's file from before it would hold.

- **Checks**: `cargo fmt`, the release build, `cargo test --release --no-fail-fast` for the workspace (the core's 646 passed, 5 ignored) and both clippy runs passed. A first `cargo test --release` failed once in the client's `a_started_process_keeps_its_exit_code_however_soon_it_ends` (the exit code not yet read), which this part does not touch; it passed alone and in the run after. `cargo xtask offline-check` was not run: the change touches no dependency point.
- **By hand**, a new game as the Ottomans (`menu start TUR`):
  - `describe` gives every one of its 299 capabilities an `as_game` field; none is true yet.
  - `session get` and `session get --as-game` answered the same.
  - `country get ENG` answered `treasury`, `power`, `inflation`, `loans` and `governing_capacity` null, as the player's view leaves them out, although the settings file said `remote_full_view=yes`: the file was read without it. With `--as-game` it answered England's treasury 73.372, its monarch points 28, 70 and 28, its loans and its governing capacity 286.52 of 562.5.
  - `army at` for Paris (183), London (236) and Stockholm's province (1) answered `[]`, and with `--as-game` the French, English and Swedish armies there, 14, 14 and 12 regiments; for Constantinople (151), in the Ottomans' sight, both answered the Byzantine army of 8 regiments.
  - The signals, read first with `--kinds battle,war_declared,province_owner_changed` so that the battles were worked out, then 14 months at speed 5 to 1446.9.11 (answering the questions that stopped the advance with their first option): read as the player, 15 `war_declared` and 27 `province_owner_changed`; read as the game, the same and 25 `battle`, numbered among them (313, 352, 372, …). The Ottomans fought no battle and saw none, so the player's view read none.
  - The framework log writes a request as the game with " as the game" after its JSON (`remote #65 {"capability":"signals","kinds":[…]} as the game: ok in 0.0 ms`), and one as the player as before.
- **`cargo xtask scenario sweep`**, in this claim's test game, from 05:24 to 05:33, another checkout's game running beside it: passed, 285 capabilities in 5 places, 3,657 requests, every answer of its shape or a refusal the catalogue has, none `as_the_game`. The test game ended with exit code 1 each time, no crash.

Not verified: no capability needs a request as the game yet (the script group, M10 to M12, is the first), so the `as_the_game` refusal and the sweep's asking such a capability both ways were tried only in the unit tests (`catalogue::tests::what_no_player_could_do_is_asked_for_only_as_the_game`, `remote::tests::each_request_acts_as_it_asks_and_its_wait_too`); a request as the game that waits (a `signals` read with `wait_ms`, an advance) was tried only in the unit test, not in the game; the settings window was not opened to see the remote control page gone; extensions were not run, since nothing they have changed.
