# 2026-11-11 The band above an event's options, drawn wrong for a player (tested by me, reproduced and fixed)

A player on Harmony 0.1.0 from the Workshop (1.37.5, the ordinary Chinese language mod, Regional Combat, the framework's frame rate without a limit) sent event windows whose first option was drawn wrong: the game's top bar's numbers in its place, a shrunken copy of other interface, or a flat dark band with the button missing; the screen flashed as such an event appeared.

The cause: an option's button is a texture its text is drawn into as the event fires, in the day, and the main thread read and set the renderer's render target for it before beginning its scene, where the framework took the presentation lock; the drawing thread drew the rest of its frame into the button ([research](../research/drawing-beside-the-day.md), "A text drawn into its texture in a day").

- **Ruled out first**: the transparency-mask repair (`core/src/repairs/masks.rs`), which frees only the hit-test bit vectors, and freed 0 MB in the player's run; the UTF-8 translation mod's `interface/topbar.gui`, which moves a few numbers by 3 px; the frame rate setting.
- **Not reproduced from the console**: a hidden test game from master (`11b7f09f`) with `dev-test-games`, the owner's playset and settings, `observer-1700.1.1` as the Ottomans; `event flavor_por.3266` and `flavor_por.3267` fired while paused and while running at speed 3, 32 screenshots, every window whole. The console's commands run in the commands' step, outside a day.
- **Reproduced with natural events**: the same game at speed 5, every event the game fired itself screenshot three times as it appeared and answered with its first option. From the 22nd event on, every frame was the first option's texture ("给他们需要的任何东西。") stretched over the screen.
- **A crossing at the function's entry failed**: `0x1596660` reads fifteen arguments, and an observer forwards at most twelve; startup refused it and the game ended before its menu, as it should.
- **Fixed**: the render target read (`0x16d8d20`) and set (`0x16d8ca0`) by the main thread in a day are crossings. The same run, six minutes: 44 events, every first option's button drawn whole with its text, no frame drawn into a button; 146 to 164 frames a second; the render target's read held 1 to 6 frames back in ten seconds, the main thread waited 10 to 30 ms in ten seconds at crossings.
- **Not verified**: the player's machine, on which the race was hit more often and with other interface; a run long enough to say it cannot come back, since it is a race; other slots of the renderer's table reached in a day.
- **Cleanup**: the test game released; its logs kept in its claim's `kept\`.
