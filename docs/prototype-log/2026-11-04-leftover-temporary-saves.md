- **Where an ironman save's time goes**, Austria-37_4-1 from 1724, speed 5, 60 s at 100 samples a second (`cargo xtask profile`): the ironman save `0x5c7ac0` was 20.9% of the main thread's samples, about 14 saves of 55 MB in the minute (each compressed by the thread afterwards, in 1.7 s), about 0.9 s each with the sampler's slowing (the main thread was suspended 18.6% of the time). Of the save: 69% writing the game state into memory (`0x14e3f00` → `0x74ff30`: the countries `0x2dc6b0` 35%, the provinces `0x9d6e60` 24%), 24% the zip entry at level 0 (`0x153b9a0` → `0x153c790`, zlib copying the data into stored blocks), the rest the file. Under the writing, the most samples of their own: the memory stream's write `0x171f290` (14%), number formatting through the C runtime (`0x15c230` → `0x1a41f30` and below, 13 to 15%), the provinces' fields (`0xa366d0`, `0xa36ce0`, 13%), and `memcpy` (`0x1a35750`, 4%).
