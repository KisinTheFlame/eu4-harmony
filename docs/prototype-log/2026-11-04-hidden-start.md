# 2026-11-04 The hidden start (tested by me)

H1 to H4 of [hidden-start.md](../plans/hidden-start.md). A player build of this branch installed with `cargo xtask install` after the framework files in the game folder were copied aside; the player's playset, a borderless 3840x2160 window. The game was claimed with the game-lock skill, which backed up the player's files. Each start was `eu4-harmony start --hidden` from the installed tool, with another program in front; a script in the scratchpad listed every 100 ms the windows of `eu4.exe` (visible or not), the foreground window and Windows' cursor.

- **First try, shown**: with `SDL_WINDOW_SHOWN` only left out of the window's flags, the window was shown 0.8 s after the framework started and took the focus. SDL 2 shows a window made without `SDL_WINDOW_HIDDEN`; the window's flags take it since.
- **Hidden**: from the start to the main menu (54 s) and through a game, no window of the process was visible at any time, the foreground window was the same throughout, and Windows' cursor moved only with the mouse of the person at the computer. `desktop.get` answered hidden, hidden start, no sound. The framework UI found the hidden window by its class, `SDL_app`.
- **Drawing and input**: screenshots of the main menu and of a game were of the full 3840 by 2160 frame. In a game started with `menu.start FRA`, `input key space` resumed and paused it, `input.get` answered the cursor held in the middle of the frame (1920, 1080), and a click moved it there; the camera stayed where it was over 22 s.
- **No sound**: the process loaded none of `dsound.dll`, `XAudio2_*.dll`, `AudioSes.dll` or `MMDevAPI.dll`.
- **Showing and hiding**: `desktop.show` made the window visible with the foreground window unchanged; `desktop.hide` hid it again, and the camera and the held cursor stayed.
- **The main menu again**: after `menu.return`, the in-process return, the window stayed hidden.
- **Full screen in the settings**: with `fullScreen=yes` and `borderless=yes`, and then with `fullScreen=yes` and `borderless=no`, the hidden start reached the main menu (58 s), hidden, with the foreground unchanged and a frame of 3840 by 2160; the game's log says it made its device with "Fullscreen=no". The framework's end of a hidden start in full screen was not reached.
- **A crash**: a developer build of this branch with the test switch `crash` crashed at the first frame of a game: nothing was shown, no crash reporter started, the process ended about a second later, and the crash folder had `exception.txt`, `meta.yml`, `minidump.dmp` and `settings.txt`. `menu.start`, waiting for its game, said the pipe broke.
- **Not tried**: `--sound`, a hidden start whose framework fails to start, the game's own error messages being left out, the input device moving the cursor while hidden, a shown start with full screen (it would have taken the display of the person at the computer), the game's own restart.
- **Cleanup**: the game was closed by ending its process after each run. `dev.toml` was removed from the game folder, the three framework files there were put back and compared equal to the copies taken before, and `settings.txt` was set back before the last runs. Releasing the game restored the player's files (`settings.txt`, the login cache and the framework's logs among them), removed the crash folder and found every file as the backup had it. The script, its records, the screenshots and the copies of the framework files were deleted.
