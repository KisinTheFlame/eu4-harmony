# 2026-10-29 The main menu after review (remote control C5, tested by me)

The final build: this branch at `Refuse a load the game's own loader could not read`, rebased onto C6's merge, with the review's changes and C1's restart reconciled (452 dependency points match; 103 hooks, 4 writes). An attempt earlier the same day with the build before its last two changes, on C1's merge (442 points), found the two problems those changes fix; it is at the end. Every request went through `eu4-harmony game`; `eu4.exe` was started directly, the single player setup's buttons clicked with `tools/game-input.ps1`. Chinese playset with the unchanged regional-combat extension, system fonts; backups as AGENTS.md says. Two test saves were put in the save games folder: `c5-broken-meta`, a copy of 法兰西1445_02_20 with one byte of its `meta` entry flipped, and `c5-damaged`, the same with 64 KiB in the middle of its `gamestate` entry zeroed, so that it no longer inflates.

- **The main menu**: `menu` said `starting`, then `main_menu` 3 s later. `menu.saves` listed 141 saves, the test saves first (`c5-damaged` FRA 1445.2.20; `c5-broken-meta` with a null player and date); `session` was `not_in_game: the main menu is open`, `menu.return` `not_in_game: no game is going on`, `menu.load c5-broken-meta` `rejected: the save cannot be read: zip entry of the wrong size`, `menu.start QQQ` `not_found`.
- **A page the player chose**: with the single player setup entered by hand, `menu` said `main_menu` (no start made in it), `menu.load` and `menu.start` were `unavailable: only from the main menu's first page`, and a screenshot after them still showed the setup.
- **A return the player made**: the setup's back button starts `eu4.exe` again, as returning to the main menu does. An `events` read waiting (`--wait-ms 60000`) when it was clicked was answered `not_ready` ("the game is returning to the main menu ...") 2.3 s after it was sent, at the restart, and a `menu` sent after it at once; the new process answered 45 s later.
- **A save the game cannot read**: `menu.load c5-damaged` was answered after 0.9 s, `rejected: the game could not read the save: it starts a game anyway, from what it read of it`. A second client's `session`, sent 0.5 s after the load, waited and was answered at the game's first frame: session 2, 1445.2.20, `FRA`. From the next request on, `session` and `time` were `not_in_game: no controllable player`, and `menu` said `game`.
- **Returning without a country to play**: there, `menu.return` answered `{"place": "ending"}`, and `menu` 0.3 s later `not_ready`. Again after a new game as France switched to spectating with `console run observe` ("Entered Spectator Mode.", then `session` `no controllable player`): `menu.return` answered `ending`, and an `events` read waiting since the last event was answered `not_ready` 0.55 s after it was sent.
- **A load**: `menu.load 阿尔达比勒1454_09_13` (a compressed text save made with the playset's mods) answered after 4.2 s: session 2, 1454.9.13, `ARL`, the save's header; a second client's `menu` said `starting`, and its `session` waited and read the same.
- **An advance when returning**: `time advance 365 --speed 1`, an `events` read waiting since the last event, then `menu.return`: the advance answered `stopped: main_menu` at 1454.9.14, with that day's event and `process`; the events read `not_ready`.
- **A start**: `menu.start FRA` answered after 6.4 s: session 1, 1444.11.11, `FRA`. A `menu` sent 0.5 s after it waited 5.6 s for the main thread to present a frame and said `starting`.
- **A start made by hand**: in the setup, France selected and its start button clicked, the game asked for the game mode; until that was confirmed `menu` said `main_menu` and `session` `the main menu is open`, as no start was made yet. Once confirmed, `menu` said `starting` (answered 3.9 s later, at the next frame presented), then `game`, and `session` read session 1, `FRA`.
- **A country with no land at the start**: `menu.start PRU` (Prussia) answered after 8.2 s with session 1, 1444.11.11, `PRU`; from the next request on, `session` and `time` were `not_in_game: no controllable player`. `menu.start` does not check that the country exists at the start date.
- **A save made with a mod the playset lacks**: `menu.load 符腾堡1445_07_19`, made with a gameplay mod not in the playset, crashed the game 2.8 s after it ran, after the save loader had returned, in the load command the main menu's frame ran (`eu4+0x88a1fb`, reading past the end of an array of the game's; research/main-menu.md). `menu.saves` does not say which mods a save was made with, and `menu.load` does not compare them with the playset.
- **Costs**: requests answered at once took under 1 ms, but the first `menu.saves`, 10.8 ms for 141 saves (in the attempt below).
- **Not seen in the running game**: a load or start given up after 30 s with no step (no start the game did not take up came about); `rejected` because the setup did not take a start; a page the player changes between a load's request and the main menu's frame that runs it (only the refusal on a page already changed was seen); a load whose first session has another player or date than its header, since the damaged save was refused by the loader check first (unit test); an ironman save with this build (the earlier runs loaded one).
- **The attempt before**, with the build on C1's merge: the main menu, a page the player chose and the return by hand went as above. `menu.load c5-damaged` was answered with session 2, 1445.2.20, `FRA`: the loader had failed (`saves: load did not establish the current world`), the header comparison let it through, and the game had no controllable player. And the second client's `session`, sent 0.5 s after that load, was answered `the main menu is open` 3 s later, at the frame presented just before the game's first: the frame the game took over in, where the main menu's frame still ran and none of the start's flags read as set. The final build fixes both: the loader's own result, and the main menu counted open only while it is the world's idler. That the second fixes it was seen only in that the final run's second clients waited, three times; the first attempt's false answer came from one frame and was not provoked again.
- **Cleanup**: the game crashed once, at the load above; its crash folder was deleted. Otherwise it was closed by ending its process. The two test saves were deleted and `settings.txt` put back; both save folders, the three settings files, `continue_game.json` and `dlc_load.json` compared equal to the backup. The framework was uninstalled, which put back the earlier `version.dll`; the backups, logs kept for the record and screenshots were deleted.
- **Rebased onto C7, not run in the game**: the branch was then rebased onto the merge of C7, which renamed C1's stop reason `game_event` to `question` (`Stop::Question`, `questions_waiting`, counted by `questions::count`, the questions `question.list` lists). The rebase kept both: C7's names and counting, and this branch's restart path (C1's restart observer answers every request through `Engine::end`) and `process` in C1's event reads and in an advance's answer. That build, with 482 dependency points, passed the build, the tests and the offline checks against `eu4.exe`, and was never started in the game.
