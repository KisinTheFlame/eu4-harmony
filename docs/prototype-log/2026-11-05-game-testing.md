# 2026-11-05 Game testing (tested by me)

G1 to G4 of [game-testing.md](../game-testing.md), with `cargo xtask game` from this branch's checkout; the game folder held the player's own install, an earlier player build, before and after. The player's playset, a borderless 3840x2160 window.

- **A claim**: `claim --purpose …` backed up the player's files into the claim's folder and copied the game folder's `version.dll`, core and command line tool into its `framework\`; the record kept the script's fields and added `folder`, `player` and `taken`.
- **Starting and stopping**: `install` then `game start` reached the main menu hidden in 50 to 56 s. The first `start` whose output went into a pipe did not return until the game ended: the game had inherited the pipe. With the game made with no handle passed on, it returned at the main menu. `start --timeout 5` ended the game and failed; `stop` ended it.
- **The queue**: with the game held, `claim --wait` as `qa` and then `qb` were listed in that order, and `claim` as `qc` without `--wait` was busy (exit 2). `qa`'s waiting command was ended; a minute later only `qb` waited. The release then went to `qb`, whose claim backed up and copied as the first had.
- **The release**: it put the player's files back ("every file is as the backup has it") and the game folder's framework files ("as they were"), printed how long the claim was held, whether the game crashed, and `kept\`, which had the framework's and the game's logs.
- **A shown start**: `qb`'s `start` after that release showed the game, since the game folder had the player's install again, which has no hidden start; it was closed at once. A hidden start into a framework without it is refused since, and was tried refused.
- **The player**: with `qb` holding a running hidden game, `claim --player --now`: `qb`'s `watch` exited at once with 4; 120 s later the claim ended the game, released `qb`'s claim (its files and the game folder put back as by `release`) and held the game for the player, 124 s in all; `release --player` freed it.
- **A crash**: a developer build with the test switch `crash`, installed within a claim with a `dev.toml`, crashed at the first frame of `menu.start FRA`, hidden. The release said the game crashed, kept the crash folder in `kept\crashes\` (`exception.txt`, `meta.yml`, `minidump.dmp`, `settings.txt`), removed it from the user folder, and removed the `dev.toml` the game folder had not had.
- **`perf-run`** on the player build within the claim: 55.9 s to the main menu, `menu.start MNG` 10.0 s, 0.85 cores paused and 1.60 at speed 5, 1444.11.11 to 1447.5.3 in 120.3 s.
- **`leak-run --rounds 1 --days 10`** on a build with the memory account within the claim: it started the game hidden, and the round took 46 s.
- **`watch` and builds**: a build with a feature while `watch` ran failed, cargo unable to replace `xtask.exe`; with `watch` moving its file aside, the same build went through.
- **Not tried**: a holder whose lease ran out taken over; a checkout still on `game-lock.ps1` beside one on the commands; a `NOT RESTORED` line from the game folder's files; `start --sound`; `kept\` removed after seven days; two sessions in two checkouts at once.
- **Cleanup**: every claim was released with every file put back. The test claims' folders and the results of `perf-run` and `leak-run` were deleted; the queue is empty.
