# 2026-11-03 Developer builds (tested by me)

This branch's uncommitted change for part C0 of [commands.md](../commands.md): the development tools as `dev-` features, their options in `dev.toml`, the test switches moved out of player builds. Built three ways: with `dev` (every tool), with `dev-command-log` alone, and the player build; each installed with `dev-install.ps1`, which copied the repository's `dev.toml` into the game folder's `eu4-harmony\`. The game claimed with the game-lock skill, the framework files in the game folder copied aside first. Seven processes, each started directly; those that started a game went to the main menu, `menu.start FRA`, the opening questions answered, then 3 days.

- **With every tool, `dev.toml` tracing `0x159c600` (3 calls), logging `daily_tick` and `buildunit`, the test notice on**: the log's first line and the report's say `developer build with the call trace, the heap census, the command log, the test switches`; the report lists the options as given and the census "at every world reset". 743 dependency points match; 132 hooks, 10 writes. The two test notices were posted at startup, the log giving their English text from the developer build's own localisation; the notice window was not looked at. Only `daily_tick` commands were logged (three; no `buildunit` was executed in those days). The census counted at the world reset of `menu.start`. `0x159c600` was not called in the run, so the trace logged nothing.
- **Tracing `0x14ca870` instead, the test notice off**: its argument count read as 1; its first three calls logged with their call site `0x14ca61a` and results, then `later calls not logged`. No notice was posted.
- **`fail-startup` on**: startup failed before any point was installed; the report says `startup FAILED` with `fail-startup is on in dev.toml's [test-switches]`, and the player was told so.
- **A misspelled option (`fail-startupp`), then an unknown section (`[commands]`)**: startup failed with the TOML error, its line and the options expected. The first run's report listed the defaults above the failure as though they had been read; the core was changed to say `dev.toml was not read` instead, and the second run's report said so.
- **With the command log alone, every section in `dev.toml`**: the first lines name only the command log; the report says of the other three tools that they are not built in and their sections are not used. 737 points match; 126 hooks. Only `daily_tick` logged.
- **The player build, the same `dev.toml` installed beside it**: the first lines carry no developer build; 731 points match, 125 hooks; nothing of the tools in the log (no census, trace, command or notice lines).
- **`release.ps1`**, run from another folder, built the player build itself and packed its three files.
- **Not verified**: the census's counts against an earlier census run; `dev-call-trace`, `dev-heap-census` and `dev-test-switches` each built alone (they were checked with clippy alone, not run); the developer build's CI steps, which run only on a pull request.
- **Cleanup**: the game was closed by ending its process.
