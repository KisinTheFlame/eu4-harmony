# 2026-11-08 What a frame's drawing reads and the next day writes (tested by me)

The same question on test games, after [what a frame's drawing reads](2026-11-08-what-a-frames-drawing-reads.md), with the watch's watchdog (`give-up-after`) and `let-run` of this branch, the developer build with the write watch, the test switches and the test games' pipes; `dev.toml` as in that run, `give-up-after = 20`, and the test switch `game-searches-armies` on, so that the day's army searches are the game's and wait for no thread of the framework's that the watch holds. The 1780.7.1 save copied into each test game's `save games`, `menu.load`, `console run observe`, `session.view TUR`, `time.advance 60` at speed 5.

- **With the driver's threads let run** (`let-run = ["nvd3dumx.dll"]`, the watchdog counting every thread's accesses): the watch began at 1780.7.21 and the map's drawing never reported; 28 minutes later the claim's lease ran out and a waiting claim took the test game, ending it. The kept log had nothing after the watch's beginning.
- **With every thread held**, the watchdog counting the main thread's accesses: the map's drawing reported as before (3.09 million), then the GUI's stopped as in the first run, and the watchdog did not give up in 30 minutes: 88 threads held, the main thread and one other in a wait, 0.02 s of CPU in 5 s. A loop that waits, touching the same heap again, reads as progress; the test game was stopped.
- **The watchdog counting new groups** (an instruction, calls and target not seen before): two rounds. Each time the GUI's drawing stopped in the driver (`nvd3dumx.dll+0x18767d` under `d3d9.dll+0x11086` under `0x16d66be` < `0x159b113` < `0x15f41b9` < `0x14dd4ee`), and the next day stopped in it too, through `d3dx9_43.dll+0x11aa4b`; the watchdog gave each up after 20 s and the game went on. The first day wrote 2.63 million times up to then, 123,412 of them to what the round's drawing had read or written; the second 2.57 million and 87,060. What they were: [research/drawing-beside-the-day.md](../research/drawing-beside-the-day.md).
