# 2026-11-03 Commands C1 to C3 (tested by me)

The developer build of ff49db0 and of the change after it, which has the layer execute its command alone instead of running the session's queue (ADR commands-run-at-once), with `dev.toml` tracing `0x26dba0` (60 calls), logging `buildunit`, `diplomaticactioncommand`, `move_order`, `cancel_movement` and the two speed commands, and posting seven test commands. Four processes, each a new game as France at 1444.11.11 started through remote control; the requests through `eu4-harmony game`.

- **Startup**: 756 dependency points matched for ff49db0, 758 for the change after it; 132 hooks, 10 writes.
- **The test commands, at the first frame of each game**: the recruit in Paris and the alliance with Scotland were carried out (France's manpower 11,798 → 10,798); the recruit in London was refused by its check (`Check`); `province=abc` (read as -1), `provinec`, `nosuchcommand` and the missing brace were refused unread, each with its reason.
- **Recruiting, paused and at speed 5**: done when the call returned (manpower 10,798 → 9,798, treasury down by 10 at the next request); London refused with the game's reason ("法兰西不是伦敦的控制者。"); artillery refused with the framework's.
- **Diplomacy**: an alliance proposal to Savoy a day in was answered `accepted`, and Savoy listed France as an ally. On the first day it was refused with the game's reason (a proposal already made that day, the test command's).
- **Army orders**: Paris's army moved to a neighbor ([184]) and to a province six away, its route the one `army.route_to` gave ([184, 179, 4697, 195, 4112, 175]), each set when the call returned, through the game's move command as written; a stop through the cancel command left no route; a move to its own province and to provinces with no route (1, 50, 1269) did nothing or were refused with `no route`; a movement-locked army's new order was refused as before. Each order raised one `army_ordered`, and none more from the route hooks.
- **Speed**: 1 → 5, 5 → 2 and 2 → 2, paused and running, one speed command a step, the speed read back as set.
- **Each call took** 0.0 to 1.3 ms in the game, 24 ms for the first recruit of a process.
- **The first build hung**: ff49db0 ran the session's queue at its safe point. At speed 5 its first command, a recruit, ran the day the queue held, which drew a frame of its own whose Present came back into the framework's safe point; the main thread waited on remote control's lock its outer call held (stack read through a non-invasive attach). The build after it executes the command alone, and ran the same requests and more without a hang.
- **The sender** (research/commands.md): a trace of `buildunit`'s key read showed the binary read-back reach it with the base keys, which the copy that ran did not keep; executed from the text read, the commands carried `sender=1` and the session's tick.
- **Not verified**: an extension's order through the layer, and its route counted as its own (remote control's orders only); a stop of an army in the middle of a step (the one tried had arrived by then); a strait; a command whose check refuses it only when executed; a session state the update executes no commands in; a save loaded, ironman, multiplayer.
- **Cleanup**: each game was closed by ending its process, the hung one too. The framework files were put back in the game folder and compared equal to the copies, and the installed `dev.toml` removed. The game-lock release restored the player's files (the framework's logs, `pdx_login_cache.txt` and `settings.txt` had changed) and compared each equal to the backup.
