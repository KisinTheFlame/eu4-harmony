# 2026-11-11 The picture stopped after a country switch, a war declared and a save continued (tested by me)

A player on Harmony 0.1.2 from the Workshop sent three troubleshooting files: the game stopped drawing after `tag MNG` in the console, as they declared war, and after continuing a save from the main menu, the sound and the days going on. All three logs end the same: no frame drawn, the frames held back by the renderer's `GetLevelDesc` (`0x16d7f30`), 888 times in ten seconds after the switch, 702 in the last stretch before the war's session was closed, 1,681 after the save was loaded (`session 2 started (from a loaded save: true)`), with texture destructions (`0x16d80f0`) beside it.

- **The setup**: a hidden test game with `dev-test-games`, a new game at 1444.11.11 as the Ottomans (`menu start`), `console run tag MNG` by remote control; the 1700 save does not do, where `tag` answers that the country has no provinces for every tag tried but the player's own.
- **Reproduced** with master before [the war overview's run](2026-11-11-war-overview-held-back.md) (`9bae5de8`): from the switch on, 0.0 frames a second, held back by `0x16d7f30` 9,772 times in ten seconds and by BeginScene (`0x16d4e00`) as often; a screenshot never answered. Sampled, the main thread was under the frame's tail, `0x80c9f0` → `0x830700` → `0x15bd460` → `0x156e0a0` → `0x156b5c0` → `0x16d7f30`: a window's text drawn into its texture at every frame ([research](../research/drawing-beside-the-day.md), "The war overview after the drawing").
- **The same cause as the war's**, which another session fixed meanwhile: a call into the renderer with the main thread holding the lock is no crossing. Tried first here, and set aside for it: only the table's functions that let something go stay crossings, the rest taken in the lock's turn; with it, after the switch, 60 to 115 frames a second.
- **With master's change** (`876637a8`), the same test game: after `tag MNG`, 107 and 121 frames a second; then war declared on Dai Viet without a casus belli (`diplomacy.declare_war`) and the game run at speed 3, 114 and 129; then the Ming's autosave at war, loaded from the main menu, 124 and 126. Not tried with the build before it: the war declared by the player and the save continued.
- **Not verified**: the player's machine and playset; why the switch makes that window draw at every frame.
- **Cleanup**: the test game released; its logs kept in its claim's `kept\`.
