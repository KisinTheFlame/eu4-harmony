# 2026-11-10 The seams between the world and the interface (tested by me)

How many pointers link the world and the interface's and the graphics' objects ([research/world-interface-seams.md](../research/world-interface-seams.md); W1 of [plans/drawing-thread.md](../plans/drawing-thread.md)). A core from master (`26556961`) built with `dev-heap-census` and `dev-test-games`, with a one-off scan added to the census in a worktree and not merged: each `memory.generation` took a step, the first scanning every live block and the game's data, the second and third comparing the world's pages paused. One hidden test game (`w1-seams`), the 1780.7.1 save ([research/late-game.md](../research/late-game.md), "Saves to test with") copied into its `save games`, `menu.load`, `console run observe`, 20 days at speed 5, paused; the player's playset and settings; nothing else ran on the machine's test games.

- **First scans, classified by allocation site alone**: the world's blocks seemed to point 319,409 times into the presentation's, but generic containers' code (`0xc9e70`, `0xc9b40`, `0x8f0e0`, `0xcc220`, `0xdf120`) allocates for both, and blocks never part of the world (a file system buffer, the job system's) counted as the world's. Classifying by what the game state reaches, a generic block by the two calls above its allocation too, and the in-game idler's, the messages' and the floating texts' code taken as the interface's, gave the figures of the note; the idler's range was first too wide (it took in `empire.cpp`'s `0x7fc110` and `0x801b60`) and was narrowed.
- **The final scan**: 8,078,092 live blocks, 1,949 MB; the world reached from the game state 7,101,064 blocks, 1,709 MB; the presentation's 605,565, 187 MB; 42,993 words from the world into the presentation's blocks in 2,052 pairs of sites; 88,962 from the presentation's into the world; the game's data 143 words into the world, 552 into the presentation's, 712 into the rest; 7.0 s, the game's threads waiting at their next allocation meanwhile.
- **Paused**: 70 pages of the world's blocks changed in about 10 s, 16,843 words in about 18 s after, nearly all the file system's read buffer.
- **30 days later**: 45,808 words in 2,076 pairs; 422 pairs had changed their count.
- **Not verified**: a player's game, open windows, hovering, other map modes, the month's turn; the blocks the census does not count; whether each counted word is a pointer and not a number that equals an address. The game ran without a crash through four starts.
- **Cleanup**: the test game released, its logs and the scan's files kept in its claim's `kept\`; the scan's code was not merged; it is kept as `seams-scan.patch` beside the scan's files.
