# 2026-11-02 Why a return after time ran crashed, and the fix (tested by me)

Nineteen processes, most of them with experiment builds (`trace`, the census on): dumps of the GUI root's elements and of the render tree by name and class from inside the game, a watch on the heap blocks of the sprites and their sprite types with the stack that freed them, a check of every drawn sprite whose sprite type was unloaded, and an observer of the show, hide, load and unload of one sprite type. Backups as AGENTS.md says, the framework files copied aside first. Driven by `eu4-harmony game`. Saves: `法兰西1495_11_19`, `英格兰1444_11_11`, and a test save made from `法兰西1445_02_20` with its `meta` dated 1821.1.1, as before.

- **Where it went wrong**: not the sprites' objects, which were all alive at the main menu and at the next session's start; the texture their sprite type caches, let go while sprites of the session still counted it. The game's `error.log` named the sprite types, one at a time: `GFX_messageicon_bg`, then `MessageSettingsButton` (research/main-menu.md).
- **`GFX_messageicon_bg`**: the in-process return now takes the session's interface down as the in-game load does, by calling the game's own in-game load with no save's name, which empties the diplomatic message icons among other things and then stops. That error was gone from the next runs.
- **`MessageSettingsButton`**: the observer showed the sprite type unloaded by the main menu, made again, with two message popups still counting it. The return now deletes the popups the message windows hold first. Deleting the message windows as well crashed the game in the main menu (their message list deleted them again) and was taken out.
- **As built**: four returns in a row, each after 30 days at speed 5 (法兰西, 英格兰, 法兰西, 英格兰), then 30 days more in a fifth session: no crash, no lazy-load error. Then, in another process: a return after 30 days; a return with the end-of-game summary open (the test save run past its end date); 30 days in 英格兰, an in-game load of 法兰西 and 10 days, a return; a new game as France and a return: no crash, no lazy-load error.
- **Not seen in the running game**: ironman returns with this build; the setup's back button; the end-of-game summary's own "退出" button (only `menu.return` with the summary open); the 20 rounds.
- **What stays**: about 1,035 GUI elements in the GUI root after each return, as before.
- **Cleanup**: the experiments' code was taken out of `core/src/census.rs`, `core/src/repairs.rs`, `core/src/ext.rs` and `core/src/game/menu/leave.rs`. `-Restore` listed what the runs changed (the framework's logs, `pdx_login_cache.txt`, `settings.txt`, `shortcuts.txt`, the test save added), put each back, removed the added save and eight crash folders, and found every file as the backup had it. The framework files in the game folder were put back and compared equal.
