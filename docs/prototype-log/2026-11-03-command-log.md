# 2026-11-03 The command log (tested by me)

Whether one observe point hears every command the game executes, and whether a command writes itself as text with the game's writer ([research/commands.md](../research/commands.md)). This branch's build with the `trace` feature and `core/src/command_log.rs`, after the build and clippy passed; the offline checks were not run, as the log's points are the trace build's and startup checks their bytes. Four processes of `eu4.exe`, started directly with `EU4HARMONY_COMMANDS=all` (one without it), the playset as installed (the Chinese one) with the regional-combat extension, each a new game as France (`menu.start FRA`), driven by `eu4-harmony game`. The game was claimed with the game-lock skill, which backed up the player's files; the framework files installed in the game folder were copied aside first.

- **Startup**: 713 dependency points match; 121 hooks, 10 writes. The first process ended at `menu.start` with the framework's fatal notice: the log read `0x2357b30` through `Memory::at`, which knows only the framework's own points. Fixed by adding the base itself, as `trace.rs` does.
- **Every executed command was logged in text**: 40,712 commands of 74 types in three processes, none failing to write. What they carry is in research/commands.md: the setup commands of a new game, the AI's, the game's `daily_tick`, and the player's `buildunit` and alliance proposal through remote control. The framework's `army.move` and `army.stop` made no command, nor did the console's `stability`.
- **Three classes ran with `sender=-1 tickstamp=65535`**: `diplomaticactioncommand`, `spend_money` and `buildunit`; the others with `sender=1` and the session's tick. Not explained; the guess is in the note.
- **Cost**: 9 to 10 µs a command. At speed 5, 10 and then 30 days took 2.0 s and 4.4 s with the log off, 1.5 and 2.6 s and 2.3 and 4.1 s with it on: no difference the runs' spread would show. In the first process `time.advance` ran at the game's start speed and took about 2 s a day; that was the speed, not the log.
- **Not verified**: reading a command's text back, which posting a command from its text needs (tried in the next section); a save loaded; ironman; a return to the main menu with the log on.
- **Cleanup**: each game was closed by ending its process. The framework files were put back in the game folder and compared equal to the copies. The game-lock release restored the player's files (the framework's logs, `continue_game.json`, `pdx_login_cache.txt`, `settings.txt`, `shortcuts.txt`, the three autosaves), found every file as the backup had it, and removed the backup. No crash folder was made. The logs of the runs are in the session's scratch folder only.
