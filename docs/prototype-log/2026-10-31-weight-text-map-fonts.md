# 2026-10-31 A weight for the text font and the map font (tested by me)

Every system font had been drawn in its regular face; the player may now choose a weight for each of the two fonts. Three runs of `eu4.exe`, started directly, Chinese playset with the unchanged regional-combat extension, at 3840x2160 with the interface scale at 1.5. This branch's build, after the build, the tests, clippy and the offline checks against `eu4.exe` passed. The first run, with the player's own framework settings, went only as far as the main menu. For the other two the framework settings were written into `settings.txt` by hand: system fonts, Microsoft YaHei for text and Noto Serif SC for the map, at weights 400 and 400, then 700 and 800. Each went from the main menu into a new game as Ming (`menu.start MNG`), the start-of-game introduction left open, the camera on province 2130 at a height of 650, never unpaused, with a screenshot through `eu4-harmony game screenshot`. Backups as AGENTS.md says, with the framework files installed in the game folder.

- **Startup**: 579 dependency points match; 106 hooks, 4 writes. The log's settings line has both faces, `body_font: Face { family: "Microsoft YaHei", weight: 700 }`.
- **A weight the font lacks**: Noto Serif SC comes in 200 to 900 without 800. The log says "settings: the font "Noto Serif SC" has no weight 800; 700 draws instead", and no notice was shown. The map page's own line names the weight asked for: "system page 4864x4864 for "Noto Serif SC" 800".
- **The pages**: the five Microsoft YaHei pages read "for "Microsoft YaHei" 700" in the second game, at the sizes and baselines they had at 400; 3168 glyphs were drawn in 1.7 s, against 3164 in 1.5 s.
- **What it looks like**: at 700 the start-of-game introduction and the top bar, its figures and its labels, are in Microsoft YaHei Bold, with the introduction's lines breaking where they did at 400. The map's names (叶尔羌, 撒里畏吾尔) are in Noto Serif SC Bold, their strokes heavier inside the same grey outline.
- **The player's own fonts**: FZPingXianYaSongS-R-GB and FZShengShiKaiShuS-EB-GB are each a family with one weight, which their data gives as 400 Regular (the second has its weight only in its name), so the weight list offers them Regular alone.
- **The settings window, tried by the player**: these runs sent it no input (the game's window was behind the player's browser, where input meant for the game reaches the player's screen; two clicks meant for the settings button landed on the taskbar before that was noticed, and no more were sent). Afterwards the player, with this build installed, went through its two weight lists: Microsoft YaHei's three weights, a weight kept or stepped down as the family changed, Noto Serif SC's seven, saving and starting again. They reported no problem; what each step showed was not written down.
- **Not seen in the running game**: the framework UI's text in a weight; a fallback family drawn in the weight asked for (all the Chinese looked at was Microsoft YaHei's; a unit test asks a fallback for the weight); a weight with bitmap fonts first.
- **Cleanup**: each game was closed by ending its process. `tools/player-state.ps1 -Restore` put back the framework's logs and `settings.txt`, `pdx_login_cache.txt` and the game's `settings.txt`, and found every file as the backup had it. The framework files installed in the game folder before the run were put back and compared equal to their backup. No save was written and no crash folder made. The backups and screenshots were deleted, but for three crops setting the two games side by side, kept outside the game, user and repository folders for the report.
