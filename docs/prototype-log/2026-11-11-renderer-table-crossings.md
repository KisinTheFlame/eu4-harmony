# 2026-11-11 Every function of the renderer's table a crossing, and the game's locks in one order (tested by me)

After the event window's fix, which made the render target's two slots crossings, every slot of the graphics back end's table but five that answer a constant was made a crossing on the main thread in a day ([research](../research/drawing-beside-the-day.md), "The graphics back end, the one way in").

- **The setup**: a hidden test game with `dev-test-games`, `observer-1700.1.1` as the Ottomans, natural events at speed 5, each screenshot as it appeared and answered with its first option; the drawing thread's log listing twenty crossings rather than three, for the run only.
- **First, every slot counted**: 108 to 119 frames a second and a frame's drawing 4.7 to 5.6 ms, against 146 to 164 and 3.3 to 3.8 in the run before. The main thread called the slot that answers 0 some 250,000 times a second; every call, and every call of the drawing thread's, went through the framework. The five slots that answer a constant are now left as they are, and the entries go on at once on any thread but the main one.
- **Then the game hung** at the first days at speed 5: the main thread waited for the presentation lock in a slot's entry, holding the critical section of the graphics' resources (`[0x242b818]`), which the drawing thread waited for in the map's drawing, holding the presentation lock. Found with a dump of the hung game (`MiniDumpWriteDump`, read with `cargo xtask crash-dump`). The game's critical sections and slim locks are now taken in one order with the presentation lock ([research](../research/drawing-beside-the-day.md), "The game's locks, in one order").
- **Afterwards, measured** (nothing else running): three minutes each, the new build and the build with the render target's slots alone, one after the other in the same test game. 150 against 152 frames a second at the median of ten-second stretches, a frame's drawing 3.9 against 4.1 ms, 14 against 13 frames held back in ten seconds, the main thread waiting 63 against 24 ms in ten seconds at crossings. A texture made held back 13 frames in three minutes, its contents written 2; the lock order took the presentation lock 500 times and held no frame back. 37 events in the two runs of the new build, every first option drawn whole; no hang.
- **Not verified**: a shown game played by a person; the late saves; locks the game takes other than through its two imports; a run long enough to rule out a lock the main thread holds before the drawing thread first takes it.
- **Cleanup**: the test game released; its logs kept in its claim's `kept\`.
