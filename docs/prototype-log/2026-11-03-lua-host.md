# 2026-11-03 The Lua host (tested by me)

L2 of [lua-extensions.md](../plans/lua-extensions.md): a Lua extension in the running game. A test mod made by `eu4-harmony new l2-check`, its `main.lua` replaced by one that calls capabilities from its handlers and logs what comes back, with a module of its own (`require("util")`); registered with `eu4-harmony link` and added to the player's playset in `dlc_load.json`. Two runs of `eu4.exe`, started directly, driven by `eu4-harmony game`: a new game as Castile, days advanced, the questions on the way answered, `menu.return`. The game was claimed with the game-lock skill, which backed up the player's files first.

- **Startup**: 707 dependency points match; the report lists "L2 Check (id l2-check, api 0.2): extension lua/main.lua loaded; 1 UI fragment(s)". The DLL-built mod in the playset, with its `manifest.json`, is no longer a Harmony mod, as planned.
- **At the top of main.lua**: `text.language()` simp_chinese, `text.get` the mod's tooltip in Chinese, `json.encode` with an army's 64-bit ID exact, the module's value; `io`, `debug`, `dofile` and `os.time` nil, `os.clock` there; `spawn` refused, "a task is started only from a handler". In the first run these lines went to `l2-check.prev.log`: the log was rotated at the extension's first write after loading, not before `main.lua` ran. Fixed between the runs, and in the second they were in `l2-check.log`.
- **From the handlers**:
  - `on_session` with `saved` nil; `game.session.get()` and `game.time.get()` with dates as tables, `game.ui.button.tooltip` set.
  - The first `on_day`'s `date` printed `1444.11.12` and compared equal to `session.get`'s date; an army's ID a Lua integer; `army.get`, `army.can_step` (true), `army.route_to` (`[2754]`), `province.get` (托雷多), `recruit.options`, `country.get`, `camera.look_at({ province = 219 })` answered as through remote control; `army.get(1)` `nil` with `not_found`; `army.move` with a string for the province raised an error naming the argument.
  - A task started with `spawn` sent `game.diplomacy.propose_alliance("POR")` and waited; `on_day` returned meanwhile; a later frame took the task up with `{ answer = "accepted" }`.
  - `army.move` answered `true`, and `army.get` then showed the route with `route_by` `this_mod`; no `on_army_ordered` for the extension's own order. `army.stop` `true`.
  - An `error` thrown on the third day was logged with its traceback, the notice "ran into an error. It goes on running" shown once, and the extension called again on the following days.
- **Extension save data**: in the second run the half-yearly autosave of 1445.1.1 called `on_save` on the main thread ("saves: wrote the data of 1 extension(s)"), which returned `{ days = 50, note = "l2" }`; `menu.load autosave` called `on_session_ended("load")`, then `on_session` with that table. `on_session_ended("return")` came with `menu.return`.
- **Cost**: stretches over 5 ms were logged: the day the task was spawned and took its first answer, 22 ms, and three of 7 to 11 ms, the first frames after the session began; not looked into further.
- **Not verified in the game**: the time limit (a unit test stops `while true do end` after about a second, and the extension after three); a handler waiting off a coroutine of its own; the button (on_frame set its visibility; it was not clicked); `game.map.paint`; an extension that fails to load, and its notice.
- **Cleanup**: each game was closed by ending its process. The three framework files in the game folder were put back and compared equal to the copies; the test mod's descriptor was removed from `mod\`. Releasing the game restored the player's files, `dlc_load.json`, the autosaves and the logs among them, and found every file as the backup had it. The test mod, scripts and copies of the run were deleted.
