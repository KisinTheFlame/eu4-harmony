# 2026-11-10 The map icons follow the drawing thread's camera (tested by me)

T3a of [drawing-thread.md](../plans/drawing-thread.md): each map icon's placing kept as the game makes it (`0x132e5c4`) and its window moved by the drawing thread, before each frame, to where its point shows with the camera then ([research/drawing-beside-the-day.md](../research/drawing-beside-the-day.md), "Where the map icons are placed"). Hidden test games from this branch's core with `dev-test-games`, the 1780.7.1 save ([research/late-game.md](../research/late-game.md), "Saves to test with") in observe mode, the camera on Constantinople (151) at a height of 500; the player's playset and settings, 3840×2160 borderless.

- **The matrix**: a first build logged the first icon placed: the matrix in `0x218d3d4e620`, the camera at `0x218d3d4e5f0`, so its `+0x30`, the camera's view, and not the placing's stack.
- **A year at speed 5**: from 1780.7.6 to 1781.8.6, no error from the icons' code in the log, no crash.
- **Screenshots** while the camera was moved at once (`camera.look_at`) 15 map pixels at a time at speed 5 showed the icons on the map, but the build before the change showed them so too: each screenshot is answered after an update, which places the icons again. They tell nothing either way.
- **Against the game's own placing**, a check built in for this run and not kept: the drawing thread kept where it put each window, and the game's next placing of the same window was compared with it, the camera moved 3 map pixels at a time 60 times at speed 5 (`camera.look_at`, at once, between updates). Of all windows compared, 92% were within a pixel; those far off had a point that had moved in the day between (a unit marching) or a window the game had given to another icon. Of 5,000 whose point had not moved, 4,979 (99.6%) were within a pixel and 21 within 10, none further.
- **Not verified**: the map dragged by the mouse in a game shown, which moves the camera through the drawing thread's own update (the camera's update needs the window's focus, which a hidden game has not); the camera's view rebuilt by that update at once rather than as the map is drawn (if not, the icons are a frame behind); icons the update hid as off the screen, which stay hidden until the next update though the camera brings them in.
- **Cleanup**: every test game released, their logs kept in their claims' `kept\`; the build before the change was in a worktree of `target\`, removed.
