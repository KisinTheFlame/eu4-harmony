# 2026-11-07 The session's panels let go with their owners (tested by me)

The windows the session's panels and the main menu's pages keep and never kill, let go with what owns each (research/main-menu.md, "Their owners"; `core/src/repairs/panels.rs`). Runs of `cargo xtask scenario growth` and `leak` within the runner's claim; first with a probe, not committed, listing at each return the windows made before the session that ended that were still there, by type name and the code that made them.

- **Before**: after eight returns, 800 windows made before the last session were there, 554 of them roots of their trees, about 100 a session: the building interface's tabs' entries, the colonisation panel, the papacy's, the ledger's, the views' choosers, the lobby's, the hot join's, the load and save windows, the country history, the summary's statistics, the right click menus, the goto box, the flagship designer, the shortcut picker, the tutorial's hints and the single player setup's start panel and ironman save chooser.
- **With the repairs, step by step**, four rounds each: 289 windows after the owners whose destructors leave them and those never deleted; 270 after the trade interface's, the diplomatic messages' icons' and the main menu's right click menu; 2 after the building interface's tabs, the one `ButtonMenuWindow` and a message entry (`message_item`, from the messages' list, not followed). The first try ended the game at a load: the reform chooser's check read a vtable no dependency point checked, and the framework stopped; it checks the chooser's deleting destructor's slot instead.
- **Twice twenty rounds of `growth`**: both passed, no crash. Over rounds 2 to 20 the game's heap held 0.62 and 0.44 MB a round, against 3.9 with these windows left and 0.78 when every window the builds made was killed; the private bytes 6.0 and 5.0 MB a round, against 10.1 to 10.3; the heaps' unused pages 7.2 and 6.1 MB.
- **A leak run of five rounds with the quarantine**: passed; the repairs' kills and deletes freed 1,201 blocks, 0.2 MB, at once, and nothing the quarantine kept was written to after. What the GUI's sweep frees of the windows killed, later, is not kept.
- **Not verified**: the windows' trees were not followed past their roots, by the probe or by a census of the GUI root; the panels' own small objects that stay without their windows (the papacy and the country history, closed and kept; the list entries' holders) were not counted; the load and save windows each in-game load makes again without letting the old ones go (read in the code; the probe, which counts only what earlier sessions made, could not show them) were not let go; a player opening these panels in a session before the return was not tried, as the runs open none.
- **Cleanup**: the probe was taken out before anything was committed. Each release put back the player's files and the game folder's framework files and found them as the backup had them; the reports and logs the releases kept were deleted.
