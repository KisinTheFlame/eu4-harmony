# 2026-11-07 Which holders keep the windows killed at a return (tested by me)

Whether the session's panels' windows can be killed at a return without the crash of "The windows killed at a return taken out": experiment builds, not committed, with that kill put back and probes added one after another, each run within the runner's claim (`cargo xtask scenario growth`, 12 to 40 rounds), the crash folders read with `cargo xtask crash-dump`.

- **Crashes**: six of nine runs ended, after 5 to 11 rounds (three passed, 12, 20 and 20 rounds), each where the next session or an in-game load's rebuild used a window the kill had let go, and at a different holder: the top-right panel's music player, deleting its tracks (`0x14a24e0`, the first crash again); a list box's entry, killing its window (`0x152e0f0`, from the list box's kill `0x1531750`, as an in-game load's rebuild let the views of `0x81ecf0` go), twice; a window's own child (`0x1547599`); the unit view's panel's window holder (`0x149aca0`); and the unit view's object at `+0x30`, on the first frame of a load (`0x1474c80`).
- **What the probes ruled out**: the music player's tracks are each panel's own, made in its build and let go with it, and none of their windows was killed. Every window killed was a window when made and when killed (`0x1d926b0`); the GUI's factory makes only windows (`0x155c260`), and the manager's make by name makes a new one each time and keeps none (`0x14e9030`). No pointer in the image's data (`.data`) led to a window killed or to any window under one. Hooks on the list box entries' kill, a window's kill of its children and the unit view's panel's holder found no window killed at an earlier return in a holder before the crashes.
- **Double kills**: each return's pass killed some windows twice, about 20: the pass kills the last made first, and a parent's kill then kills them again through its list boxes (`0x152e0f0`). A kill sets `+0xf4` and kills what the window holds; nothing is let go there, so this is not a double free.
- **Reading**: the windows killed are held, through many different holders, by objects that outlive the return; which ones, and how a later session's objects come to hold them, was not found. Killing every window the builds made that nothing killed cannot be made safe by leaving out one holder. The windows that stay have to go with what makes them, as the map modes' and the outliner's do (research/main-menu.md, "Which windows stay").
- **Cleanup**: the probes and the kill put back were taken out before anything was committed. Each release put back the player's files and the game folder's framework files and found them as the backup had them; the reports, dumps and logs the releases kept were deleted.
