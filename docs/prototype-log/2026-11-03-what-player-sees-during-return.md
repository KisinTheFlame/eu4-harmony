# 2026-11-03 What the player sees during a return and an in-game load (tested by me)

The player had seen the game's window flicker a few times and the loading screen of the game's start during an in-process return from an ironman game, and a flicker now and then during an in-game load. One run of the installed build (master at `9b013d5`), started directly, driven by `eu4-harmony game`, the game borderless at 3840×2160 with vsync and 8× multisampling: the ironman save `H-Test` (Hungary, 1444.11.11) loaded from the main menu, `menu.return`, the save loaded again, `menu.load` from the session, loaded once more and `menu.return`. The screen was recorded at 60 frames a second with ffmpeg (`ddagrab`); the last return was watched with `IsHungAppWindow` and the foreground window every 50 ms. The game was claimed with the game-lock skill.

- **The flicker is Windows' "not responding" window**: the in-process return ran 5.8 s and 5.3 s on the main thread, and the in-game load 10.0 s, without the game taking its window's messages. At the last return, 4.1 s after `menu.return`, `IsHungAppWindow` turned true and a window of class `Ghost`, "Europa Universalis IV (未响应)", took the foreground in the game's place; 1.2 s later, once the main menu took over, the game's own window was back. In the recordings the taskbar came up over the game at each change: in the first return 4.9 s after the still notice, for 1.5 s, until the main menu's first frames; in the in-game load for a frame, as the load ended. The still notice itself was drawn over the frame the game had last presented, as meant.
- **The loading screen is the main menu's**: 0.4 s after the switch to the new main menu, the window showed the loading screen's marks and tip over black; the map behind the main menu faded in under them, and the main menu's title came 2 s later, as at startup. The painting the player saw is presented before that, once, as the main menu takes over (docs/research/main-menu.md, "The application's idler switch", found in the code afterwards and traced on 2026-11-06); the recording has no frame of it, which fits the ghost window showing the game's last frame over its presents at that time, but was not checked.
- **Not verified**: the player's own ways out (the return question, the load button), which reach the same steps; a window in exclusive full screen; how long a load runs before Windows calls the game hung on other machines (5 s by default).
- **Cleanup**: the game was closed by ending its process. Releasing the game restored the player's files, the `H-Test` saves rewritten by the ironman saves among them, and found every file as the backup had it. The recordings and scripts were in the session's scratch folder.
