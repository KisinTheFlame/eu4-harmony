# 2026-11-11 The off-screen passes' rebuilds at the frame's preparation (tested by me)

The race [research/map-drawing-reads.md](../research/map-drawing-reads.md) found: the drawing thread ran the map's off-screen passes (`0x10a51e0`), whose rebuild of the provinces' texture empties a list of provinces the day appends to and reads the provinces as the day changes them, with no lock between them. The main thread now runs the passes at the frame's preparation, after the first steps and before the names, and the drawing thread's call is given five bytes of the framework's that ask for no rebuild. A hidden test game from this branch's core with `dev-test-games`, the 1780.7.1 save in observe mode, at speed 5 (`time.advance`), the camera moved 8 map pixels every 100 ms by `camera.look_at`; the player's playset and settings, 3840×2160 borderless, a display of 144 Hz.

- **How often a rebuild is asked for**, a count built in for this run and not kept: about 870 times in two game years, the provinces' one (`+0x339`) each time; so before this the drawing thread ran the rebuild nearly every day, against the day's appends.
- **Two game years**: 36 s, the days at their pace (49 ms a day); 118 to 130 frames a second, 20 to 46 late in ten seconds, 0 to 3 held back (the monthly refresh, a port's model), the longest gap 154 to 175 ms. No crash, no error in the log.
- **Not verified**: the provinces' texture seen to change as it should in a game shown (an owner's change on the map); whether the race had ever faulted before (no crash of the drawing thread in `0x12efe40` or `0x12ef5d0` is among the runs' kept folders, which were not all searched); the cost of the rebuild on the main thread, not measured on its own.
