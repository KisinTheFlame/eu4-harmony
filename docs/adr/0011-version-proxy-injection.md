# 通过 version.dll 代理进入游戏进程

框架改用游戏根目录下的 `version.dll` 代理进入 eu4 进程，取代 `winmm.dll`（ADR 0001），`eu4.exe` 仍然不动。eu4.exe 静态导入 `VERSION.dll`，中文字体插件也靠它加载；框架有了自己的 Unicode 模块（ADR 0010）之后，占用这个入口就能让字体插件不再被加载，进程里只有框架在改文字相关的代码，不必处理两者共存。

根目录原有的 `version.dll`（通常是字体插件的加载器）按安装说明移到 `eu4-harmony/` 下备份，代理不加载它，卸载时再放回原处。`plugins/` 下的插件文件不再被加载，可以删掉。切换在 Unicode 模块的第一个文字钩子启用之前完成。

## Considered Options

- **保留 winmm，检测到字体插件就拒绝运行**：玩家得自己去卸插件；而且两边改的是同一批文字代码，一旦同时加载就会乱码或崩溃。
- **链式加载原有的 version.dll**（winmm 代理对原有 `winmm.dll` 的做法）：会把字体插件一起带进来，正是要避免的。

## Consequences

- 其他同样靠 `version.dll` 加载的插件也不会再被加载。
- winmm 代理从未对外分发，不需要给玩家做迁移；开发机上的 `winmm.dll` 由开发安装脚本清掉。
- ADR 0001 中与入口无关的结论不变：`DllMain` 处于加载器锁内，只做最少的工作。
