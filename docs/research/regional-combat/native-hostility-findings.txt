Date: 2026-10-26
Baseline SHA256: 97dd63a811487fbe2c917f2c15b1e68f7222bef74a833889cf943c8010049d5e.
Only the frozen exe and existing static material were analyzed; no running game process was read, attached to or manipulated.
RVAs must be added to the actual module base. Ghidra 12.1.4, -noanalysis -readOnly; raw results in work/native-hostility.

Conclusions
The later static closure of FOW is recorded in native-fow-findings.txt: province +0x959 bit0x20 AND +0x958 bit0x02 together form the current player's fog-hidden cache.
This file keeps the unconfirmed state of the earlier exploration below; use the later report's evidence, epoch/tag limits and conditions still awaiting runtime verification.
Located for the next round of read-only runtime verification: the general army hostility predicate RVA0xd54a60, and the player country tag getter RVA0x811b20.
The hostility predicate reads ordinary countries' hostility records, covers countries at war, and has exceptions for special countries and rebels; it has no troop-strength threshold.
The province access predicate at army vtable+0x120 is RVA0x1a2280; it is not equivalent to the final path, and it also allows some transport cases.
No FOW predicate for "currently visible enemy armies" has been proven yet. The territory-discovered bitset cannot be taken as current vision, and see-through target search must not be enabled on that basis.
Everything below is static evidence; function return values and compatibility across versions have not been measured.

1. General army hostility predicate
  using HostileFn = uint8_t (__fastcall *)(void* armyA, void* armyB);
  RVA 0xd54a60, Windows x64 RCX=armyA, RDX=armyB; only AL of the return is valid.
  Do not treat the whole RAX as a bool: the return paths rewrite only the low 8 bits, and the upper bits may still hold a country index or pointer.
  Both objects must be live objects in the current stable world; call only on the confirmed native game thread at a safe point.

Core static evidence (work/native-integration/pseudocode1.txt, ADDRESS140d54a60):
  army+0xd0: CountryTag qword of the owning country; the index is int16(tag >>32).
  country objects come from the 8-byte pointer array at *(*(global0x233d8d0)+0x118).
  country+0x1548: pointer to the hostility record array; country+0x1554: record count; stride16, the first int is the other country's index.
  The same country returns false straight away; an ordinary country returns true if it hits one of these records.
  The special country indices global0x233d8a4, 0x233d8d8, 0x233d8dc go to a special hostility branch.
  Of these, 0x233d8a4 matches the rebel filter in the original rebel-suppression selector; the other two are unnamed and should not be hard-coded on a guess.
  The related CountryTag at army+0xe0 is used for cross-exclusion; its meaning is not proven to be the controlling country. Do not replace this with hand-written relations based on owner alone.
  The faction pointer at army+0x188 and 0xa95f60 handle the rebel exceptions; armies of the same rebel faction cannot simply be taken as hostile to each other.
  Some global/TLS modes enable the vslot+0x90 check and the vslot+0x60 -> 0x1a8b70 conversion, to choose a different country for relations.
  So calling this native predicate directly is better than copying only the country record table.
  The query writes no army, country or path, but may lazily initialize the current thread's TLS through 0x1a334c0; do not call it from an arbitrary foreign worker thread.

Boundary with the original rebel-suppression logic:
  selector0x1c8860 first filters specifically for rebels and then calls this predicate; it also calls 0xd46800 to compute military strength and makes a separate comparison.
  These outer rebel-only and strength rules are not part of HostileFn; the new policy layer should not copy them.
  HostileFn does not prove visibility, that a province belongs to our own country, that a path is feasible, or that a target can be pursued.
  Verify ownArmy/enemyArmy, ownArmy/friendlyArmy, ownArmy/neutralArmy and ownArmy/rebelArmy separately, plus the reversed arguments.
  Keep the direction the caller needs; do not assume without verification that every special exception is fully symmetric.

2. Current player country tag getter
  using PlayerTagFn = uint64_t* (__fastcall *)(void* unused, uint64_t* out);
  RVA0x811b20..0x811b55, RCX unused, RDX=8-byte output buffer, RAX=out.
  source=*(base+0x233fe78), that is, world.
  if byte(world+0x1e66)==7 && byte(world+0x1e6f)!=0:
      *out=uint64(world+0x1e68)
  else:
      *out=uint64(world+0x1e60)
  Raw targeted result: work/native-hostility/pseudocode2.txt.
  The separate unit UI path 0xd423b0 repeats this branch and compares with the country at army+0xd0, which supports its meaning as the effective player country.
  Do not always read world+0x1e60 alone; in special observe/switch modes there is another source. The name of enum value 7 is not yet confirmed.
  The getter does not check that world is non-null, that the tag is legal or that the index is in bounds; the adapter must first confirm that the game is loaded, the world is stable and the country is controllable.
  Resolving the country pointer still needs a check against the manager array's real length and a valid tag; do not use a signed index blindly.

3. Native province access predicate (not full pathfinding)
  Main army vtable RVA0x1c42540 +0x120 -> RVA0x1a2280.
  using ProvinceAccessFn = uint8_t (__fastcall *)(void* army, void* province,
      uint8_t p3, uint8_t p4, uint8_t p5, uint64_t p6,
      void* tooltip, uint8_t p8, uint64_t p9);
  The nine-parameter form reproducible from the native rebel-suppression caller:
      access(army, province, 0, 0, 0, 0x2d2d2d, nullptr, 0, 0)
  The full meanings of p3/p4/p5/p8 and p6 are unnamed; use only this observed combination of arguments.
  Only AL of the return is valid; do not use the whole RAX. tooltip=null and p3=0 avoid the visible-text building and logging paths.
  The wrapper reads the province's terrain/country and army-related state, and mainly delegates to 0xd447d0.
  When mapdata+0x228 bit3 does not satisfy the land branch, it calls 0x9dd6a0(province,army,-1), and on success may also return true.
  So "native access is true" does not prove that no sea transport is needed. The enhancement needs graph-edge limits to land and allowed straits, and then lets the native move order validate the path.
  It has not yet been proven recursively that no callee makes lazy cache writes; keep to the native thread's timing, watch the results, and do not make batch calls from an outside thread.
  Raw targeted result: work/native-hostility/pseudocode1.txt, ADDRESS1401a2280.

4. FOW limits and wrong candidates ruled out
  In 0x1a2280, province+0x5e0 is a bit looked up by country index, gated by province+0x959 bit0x10.
  This looks more like a discovery/access constraint; there is not enough evidence to identify it as current visibility of a province or of enemy armies.
  0xd41870 only looks at the two sides' participant lists/unit arrays of the battle object at army+0xc0; it is not FOW.
  0xd3f490 changes the army owner and the owner of its regiments; it is a transfer of ownership and cannot be called as a read-only query.
  Main vslot+0xa8=0xd3fd30 changes the province at army+0xe8 and notifies the UI/province lists; it is a location update for movement and cannot be used as a read-only query.
  Main vslot+0xb0=0xd4cbc0 sums regiment fields and compares with a global threshold; it is not visibility.
  Main vslot+0x90=0x1a8b00 reads army+0x227 and main vslot+0x98=0x1a8c10 reads army+0x233; both are gated by the same global/TLS condition.
  Main vslot+0x10=0xd41ae0 compares the country tag given by the object at army+0x140 with the owner; nothing proves a FOW meaning here either.
  Raw results for the above: work/native-hostility/pseudocode3.txt. The ruled-out list is kept so later work does not repeat the same guesses.
  The map coloring provider0x12fdcb0 only outputs province colors; its existence says nothing about enemy armies being visible.
  Until FOW is verified, the adapter must keep enemy visibility at Unknown/false and must not treat the world's full army table as the visible list.
  If the product first verifies only occupied-province targets, it should still separately confirm the ownership/controller of its own territory and reachability, and must not substitute EnemyArmies for them.
