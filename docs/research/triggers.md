# Triggers and their tooltips (for capabilities over script content)

Baseline 1.37.5. All addresses are RVAs. Read from eu4.exe on 2026-11-05 with `cargo xtask disasm` (`core/examples/disasm.rs`) and a scan of the image for direct calls, absolute pointers and the token table. Nothing here was tried in the running game. "Inferred" marks what comes from the shape of the code rather than from code read for that purpose. Terms: a trigger is a parsed condition block, a scope the object it is evaluated in ([architecture.md](architecture.md) "Script").

## The trigger object

- **Every trigger** is a persistent object with the layout of [architecture.md](architecture.md); a block keeps its children in the game's array type: data `+8` (pointers to child triggers), capacity `+0x10` (i32), count `+0x14` (i32), with room for four children in place at `+0x18` (the base constructor `0xb89710` points `+8` at `+0x18` and sets the capacity to 4). `+0x38` is a second vtable (`0x1c38090`, `0x1c37fd0` for content triggers), the reader interface: a reader that dispatches a key to a trigger at `+X` calls `+X+0x38`'s `+0x18`. `+0x40` the persistent type `0x165`. The base constructor also adds the trigger to a global set (`[0x2340010]`, under the lock at `0x23582b0`).
- **The vtable** (read from the `is_rival` vtable `0x1cf7d10` and the block vtables below):
  - `+0x30` evaluate: `(trigger, scope*) -> bool`.
  - `+0x48` its own line: `(trigger, out std::string, scope*, bool negated, int indent) -> out`, the string constructed by the callee (returned by value). A leaf writes its localized sentence, without bullet or color (`is_rival`'s `0xc84920`: `IS_A_RIVAL_TRIGGER`, or `IS_NOT_A_RIVAL_TRIGGER` when `negated`). A block's is `0x4ef350`, an empty string.
  - `+0x50` the lines of its children: `(trigger, out std::string, scope*, bool negated, int indent, char mode) -> out`. Leaves share `0xb97cd0`, which with no children writes nothing (838 vtables hold it).
  - `+0x58` (`0xb97f60`) calls `+0x58` of every child with the same arguments: a walk whose purpose was not worked out. `+0x60` (`0xb97ff0` in leaves) evaluates and counts: `(trigger, scope*, int* passed, int* total)`.
- **The blocks**:
  - The **content trigger** (vtable `0x1c38010`, `0x78` bytes, constructor `0x8b0f0`: the base, then `+0x68` a pointer and `+0x70` a byte, both zero, purpose not established) is what decisions, missions, reforms, policies and privileges embed for `potential`, `allow`, `trigger`, `can_select` and the like. The root block `0x1c380d0` (`0x68` bytes, made by `0x24d630`) and `0x1c38010` share evaluate `0xb98200` and children-lines `0xb98260`.
  - **`0xb98200` evaluate**: true when every child's `+0x30` is true; an empty block is true.
  - The **AND block** inside script (`and = { }`, vtable `0x1cc08d8`): evaluate `0xb98200`, children-lines `0x8be3e0`.

## Writing the conditions as text

- **`0xb97cd0`(trigger, out, scope, negated, indent, mode)** writes a block's children, and is what every interface caller below calls on a content trigger. For each child, in order:
  - when `indent` is 0, it evaluates the child (`+0x30`); at any other indent it does not, and takes the child as failed;
  - it asks the child's own line (`+0x48`, with `indent`); when that is not empty and the line is to be shown, it starts a new line (appends `"\n"`, the `std::string` at `0x23266f8`, unless `out` already ends in one), indents (`0x14bf770`(out, n): three spaces, `0x232b720`, per level), writes the mark (`0x14bf690`), then the line;
  - then appends the child's own children (`+0x50` with the same `indent` and `mode`; a block raises the indent for its children itself).
- **Which lines are shown**: `mode` 0, all; 1, those whose result differs from `negated` (the ones that hold); 2, those whose result equals `negated` (the ones that fail). The filter applies only at indent 0: deeper lines are always shown, so a failing `OR` at the top is listed with all of its alternatives. The game passes 2 itself at `0x1ed4aa` and `0xdefb8d`, and 1 at `0xdefc63`; every content view below passes 0.
- **The mark** (`0x14bf690`(out, result, negated, indent)): at indent 0 or less, `"£yes "` when `result != negated`, otherwise `"£no "` (`0x14bf460` and `0x14bf530`, from `0x1cbab08` `a3 79 65 73 20`, `£` being `0xa3` in the game's text). Deeper lines get no mark. So the game marks a condition by an inline icon (`£yes£`/`£no£`, the green tick and red cross), not by a color code; the leaf lines read here carry no `§` codes. Whether some leaves color their own text was not checked across all of them.
- **A nested block's header** (`0x8be3e0` for `and = { }`, `0xb98260` for a content trigger at indent above 0, and only when it has more than one child): its result (`0xb98200`), indent and mark as above, then the localized `AND_TRIGGER_STARTS` (`OR_TRIGGER_STARTS` when `negated`, so a `NOT` around an AND reads as "one of") followed by `":\n"`, then its children at `indent + 1`. With one child it writes only that child's lines.
- **`0xb98260`** at indent 0 or below is `0xb97cd0` with the same arguments, so a content trigger's `+0x50` and `0xb97cd0` give the same text at the top. `0xb98020`(trigger), which `0xb97cd0` calls first, counts the children it will list; with none left it lowers the indent by one (inferred).
- **What the framework would call**: `0xb97cd0`(content trigger, &out, scope, 0, 0, 2) for the failing conditions only, or with mode 0 for all of them, as the views do, then `0xb98200`(trigger, scope) for the verdict. The caller owns the returned `std::string` (destroyed with `0x95660`).

## The scope

- **A scope** (`0xd0` bytes, vtable `0x1c38158`, persistent type `0x165` at `+8`): `+0x10`, `+0x18`, `+0x20` pointers to scopes (ROOT, FROM and PREV by their use, inferred; a scope made fresh points all three at itself, a copy owns copies of another's at `+0xb0`, `+0xb8`, `+0xc0`); `+0x28` the province (i32, 0 for none); `+0x2c` the country, a tag (8 bytes, valid byte at `+0x33`); `+0x34` u32 1; `+0x38`, `+0x3c`, `+0x40` i32 (the last two copied from the first by `0xcf6a0`; meaning not established); `+0x44` a second tag that takes precedence when its valid byte `+0x4b` is set ([questions-and-offers.md](questions-and-offers.md)); `+0x68`, `+0x80`, `+0x98` containers the destructor frees (`0x943e0`, `0x946d0`); `+0xc8` a pointer to a `std::string` naming what is being evaluated, for error messages (`0x8d4da0` points it at "<mission>.IsFulfilled" around the evaluation and puts back the old one). `0xbcff40` and `0xbd0640` log "Trigger condition set on the wrong scope" through it.
- **Making one for a country**: `0xcfb90`(scope, tag, 0) (it calls `0x94590`(scope, tag, province 0, 0) and returns the scope; callers `0x79fa9a`, `0x108b77b` pass 0 as the last argument). The interface does the same inline, as the policy check (`0x958f68`–`0x959005`), the reform tooltip (`0x105aeac`–`0x105af3d`), the estate check (`0x71ee51`–`0x71eed9`) and the mission check (`0x8d4fe2`–`0x8d5064`) show: every field zero but the vtable, `+8` `0x165`, `+0x10`/`+0x18`/`+0x20` the scope itself, `+0x34` 1, `+0x44` `---` with `+0x4b` 0, and the country's tag at `+0x2c`.
- **For a province**: `0x94890`(scope, 0) makes an empty one (tag `---`), then `0x6f7ba0`(scope, province) sets `+0x28` and a `---` country (as `0x3050d7`–`0x3050e6` does). `0x6f7bd0`(scope, tag) sets the country and province 0. Triggers that need a country take the province's owner (questions-and-offers.md).
- **Destroying one**: `0x947f0`(scope) (not deleting; frees the owned scopes and the containers). The inline scopes above free the same fields inline.
- **Copying one**: `0xcf6a0`(new, source), as questions-and-offers.md describes.

## The content, where its triggers are and where the interface shows them

The token ids come from the token table in `.rdata` (records of a u32 id followed by the name): `potential` `0x2cb8`, `allow` `0x2cb9`, `trigger` `0x2966`, `can_select` `0x3743`, `can_revoke` `0x3987`, `is_valid` `0x3a0f`, `provinces_to_highlight` `0x380f`, `ai_will_do` `0x2a46`, `potential_on_load` `0x3818`; `effect` is `0x59` by its use (not found in the table).

- **Decisions** (decision.cpp; `0x268` bytes, constructor `0x4877d0`, vtable `0x1c66920`, key reader `0x487cc0`): `+0x10` the key (`std::string`); `+0x30` `potential`; `+0xa8` `allow`; `+0x120` `provinces_to_highlight`; `+0x198` the effect; `+0x1d0` `ai_will_do`; `+0x20c` `major` (token `0x2d12`, a byte; the view lists those apart, with their own entry type).
  - **Kept**: `[0x242bb18]`, made by `0x488160` (`0x28` bytes): `+0` count, `+4` 511 buckets, `+8` the buckets (nodes of `0x10`: decision, next), hash `(h + c) × 0x3d` over the key; `+0x10` a `std::vector` of the decisions in load order (begin `+0x10`, end `+0x18`), which the decisions view walks.
  - **The view** (`0xfcb190`) walks that vector, evaluates `potential` (`+0x30`'s children, `0xfcb2f6`) and then `allow` (`0xfcb33b`) on the scope at view `+0x138`, and sorts the decisions into allowed and not, major or not; each list entry (`0x1062710`) keeps the decision at `+0x2f0` and its own copy of the scope at `+0x300`. The entry's tooltip (`0x1063020`, from `0xfceae7`) writes `allow` with `0xb97cd0`(decision `+0xa8`, out, entry `+0x300`, 0, 0, 0) for its `info_icon` (`0x10632c4`); the `select_button` shows the effect. Taking one (`0x1063660`) calls `0x488050`(database, decision, scope), which posts a `0x140`-byte command (vtable `0x1c66c18`, the key at `+0x50`, a copy of the scope at `+0x70`) with `0x14ca2d0`. How the view builds its scope at `+0x138` was not read.
- **Missions** (mission.cpp): a mission (`0x1f8` bytes, vtable `0x1cc21c8`, made in the series reader at `0x8d768d`, key reader `0x8d5230`): `+0x10` the key; `+0x70` `trigger`; `+0xe8` the effect; `+0x180` `provinces_to_highlight`. A series (`0x140` bytes, vtable `0x1cc2188`, reader `0x8d75f0`): `+0x10` the key, `+0x30` `potential`, `+0xa8` `potential_on_load`.
  - **Kept**: the mission manager `[0x242bd00]` (`0x98` bytes, vtable `0x1c38348`, made by `0x8d5810`), with two `std::unordered_map`s at `+0x18` and `+0x58`; the loader adds each series to an array and to a map keyed by FNV-1a over its key (`0x8d65b3`). Which map holds series and which missions, and where the array is, was not worked out.
  - **The check** `0x8d4fc0`(mission, tag) builds a country scope inline and says whether the mission can be completed: not already completed (`0x1796c0`(country, mission)), prerequisites done (`0x8d4e50`), and `trigger` holds (`0x8d4da0`(mission, scope) → `0xb98200` on `+0x70`).
  - **The view's tooltip** (`0xfc01e0`; the entry keeps the mission at `+0x18` and a scope at `+0x20`, which it copies) writes `trigger` with `0xb97cd0`(mission `+0x70`, out, scope, 0, 0, 0) at `0xfc0cc5`, after `COMPLETE_MISSION` or `CANNOT_COMPLETE_MISSION` by `0x8d4fc0`.
- **Government reforms** (`0x5c0` bytes, constructor `0x7a15b0`, vtable `0x1cb2858`, key reader `0x7a1ae0`): `+0x1b0` `potential`, `+0x228` `trigger`, `+0x2a0` `allow`.
  - **Kept**: `[0x242bc80]`, made by `0x7a73c0` (`0x8e8` bytes): an owning array of class `0x1c3d1e0` at `+0` (data `+8`, count `+0x14`, as diplomacy.md's war goal list) and a `std::unordered_map` at `+0x18`; the reader of a file is `0x7a7e60`.
  - **The view's tooltips**: `0x105abf0` writes `trigger` (`0xb97cd0`(reform `+0x228`, …, mode 0) at `0x105b546`; the entry keeps the reform at `+0x110`) on an inline scope of the player's country (`0x105aeac`); `0x105bbc0` writes `potential` (`+0x1b0`, `0x105c3cb`, entry `+0x160`) under `CHANGE_REFORM_POTENTIAL` / `CONDITIONS`. Where the view shows `allow` was not found.
- **Policies** (`0x330` bytes, made in the loader `0x9581b0`, vtable `0x1ccfd40`, key reader `0x9574a0`): `+0x158` the key; `+0x178` the category (0, 1, 2 for the tokens `0x28ac`, `0x28aa`, `0x28ab`; the view's administrative, diplomatic and military lists, inferred); `+0x180` `potential`; `+0x1f8` `allow`.
  - **Kept**: `[0x242bd78]`, made by `0x957700`, the same `0x28`-byte table as the decisions'; `0x8525e0`(table, key `std::string`) finds one by its key (compared at `+0x158`).
  - **The check** `0x958e10`(country `+0x140`, policy, reasons `std::string*` or null) -> bool: refuses a policy the country has (`ALREADY_HAS_POLICY`), builds a scope for the tag at `[country +0x140]` inline, evaluates `allow` and, given a string, appends `0xb97cd0`(policy `+0x1f8`, …, mode 0) (`0x959091`); then the slots (`MAX_POLICIES_ALREADY`). Called by the policy view (`0xfc9c75`, `0xfc9f28`, `0xfce315`) and by the command's check `0x48b300`, which finds the policy by key with `0x8525e0`.
- **Estate privileges** (estates; constructor `0x729a90`, vtable `0x1cadc48`, key reader `0x72d330`): `+0x498` `can_select`; `+0x510` and `+0x588` the two triggers the reader's jump table reaches (`can_revoke` and `is_valid` by their use, inferred: `0x72ce60` shows `+0x510` for revoking, `0x6c7300` evaluates `+0x588` first); `+0x858` the land share it takes; `+0x860` a byte that makes it irrevocable.
  - **The checks**: `0x72cc70`(privilege, scope, reasons or null) -> bool, crown land (`ESTATE_NOT_ENOUGH_CROWNLAND`) and `can_select` (`0x72cd89`, mode 0); `0x72ce60`(privilege, scope, reasons) for revoking (`+0x510`, or `estate_privilege_cannot_be_revoked`). The estate's own checks `0x71edf0`(estate, &tag, privilege, reasons) (granting: builds the country scope inline, then `0x72cc70` and the estate's limits) and `0x71f430` (revoking) are what the privilege tooltip (`0x1096fa0`: `CANNOT_GRANT_PRIVILEGE`, `GRANT_PRIVILEGE_DESC`) calls.
  - **Kept**: not established; the estate keeps its privileges in a `std::map` whose nodes hold the privilege with an i32 at its `+0x10` (`0x1097be0`).
- **Idea groups**: the idea view's tooltip (`0x139d080`, `IDEA_GROUP_CANNOT_TAKE`) writes `0xb97cd0` on `[[entry +0x138] +0x198] +0xc0`, by its place the idea group's `trigger` (inferred, not read from the reader).

## Calling them outside the interface

- **Read-only** (inferred): evaluating and writing touch the trigger, the scope and the world; the only write seen into the scope is `+0xc8`, so each call should have a scope of its own. The AI evaluates triggers in its parallel per-country update (architecture.md "The AI"), so evaluation is presumably safe to run alongside other readers but not alongside the game changing the state: the framework's safe point on the main thread, where the views also run, is the place.
- **Statics**: the mark and indent strings are function statics guarded by the compiler's thread-safe initialization (`gs:[0x58]` checks at `0x14bf798`, `0x14bf4a0`, `0x14bf570`). Localisation lookups (`0x14b34a0`) read the shared table.
- **Constructing triggers** takes a global lock (`0x23582b0`); the framework need not construct any.
- **The scope's error name**: a trigger on the wrong scope logs through `+0xc8`; a scope made with it null logs without a name (inferred from `0xbcff40`'s strings).

- Scope `+0x38`–`+0x40`, `+0x68`–`+0x98` (saved scopes and variables are guesses), and how the decisions view builds the scope at its `+0x138`.
- Whether any leaf trigger writes color codes into its own line; the ones read write none.
- The mission manager's maps; how the interface lists a country's missions (its mission slots on the country); the estate privileges' database and the privilege's key.
- `allow` of a government reform in the interface; the privilege triggers at `+0x510` and `+0x588` by token.
- Estate interactions (agendas: `0x725630` writes their conditions with `0xb97cd0`), parliament issues, subject interactions, idea groups by token: not read.
- Nothing here was run in the game: the text the framework would get from `0xb97cd0` with mode 2 is inferred from the code.
