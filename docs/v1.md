# 初版方案

状态：已定稿（2026-10-27）。术语见 [GLOSSARY.md](../GLOSSARY.md)，难以撤销的决定见 [adr/](adr/)。

## 目标与范围

- **目标**：先完成框架，再把 regional-combat 移植为框架上的 Mod，另附一个 hello 示例 Mod。框架能力按通用方式设计，不为移植让步。
- **面向**：初版只给作者自己用。接口版本 0.x，不承诺兼容。
- **仓库**：框架仓库放代理、核心、SDK、脚手架和 hello 示例；regional-combat 的移植留在自己的仓库（[ADR 0004](adr/0004-ports-live-outside-framework-repo.md)）。
- **命名**：面向用户的目录和文件一律用 `eu4-harmony` 前缀，不单独用 `harmony`。

## 安装与进程

- **入口**：游戏根目录的 `winmm.dll` 代理，`eu4.exe` 不动（[ADR 0001](adr/0001-winmm-proxy-injection.md)）。
- **安装**：发一个压缩包加安装说明，把 `winmm.dll` 和 `eu4-harmony/` 文件夹复制到游戏根目录。框架核心和框架自己的界面资源都在 `eu4-harmony/` 里。根目录原本已有 `winmm.dll` 时，说明要求先把它移进 `eu4-harmony/`，代理会链式加载它。卸载就是删掉这些文件，再把移走的 `winmm.dll` 放回原处。框架本身不经创意工坊分发或更新。
- **已登记底本**：原版 1.37.5（`9ad3efe1…`）和 unrestricted（`97dd63…`）。两者节布局相同，原有节内只差 138 字节。
- **未登记 exe**：原有各节的位置和大小与某个已登记底本一致，且每个依赖点（一个地址加一段期望字节，默认取函数开头 16 字节）都一致，就当作该底本使用；否则游戏照常启动、不加载扩展，并提示不一致之处。

## 扩展

- **形态**：导出 C ABI 的原生 DLL（[ADR 0002](adr/0002-native-dll-extensions.md)）。扩展是 Rust 工程，通过 Rust SDK 使用能力；框架用 C++ 和 Rust 开发。
- **SDK 与核心之间**：扩展导出一个入口函数，框架传入一张带版本号和长度的函数表；新增能力只在末尾追加。
- **能力边界**：扩展只能使用框架提供的能力；符号、挂钩、内存读写、原生调用只在框架内部使用（[ADR 0005](adr/0005-extensions-use-capabilities-only.md)）。
- **发现与启用**：普通 Paradox mod 加 `eu4-harmony/manifest.json`；以 `dlc_load.json` 为准，游戏启动时加载一次（[ADR 0003](adr/0003-discover-extensions-via-paradox-mods.md)）。合集中启用即加载，不做授权确认。
- **清单**：`id`、`api_version`、`extension`（DLL 相对路径）、`ui`（要注入的界面片段）。`id` 由作者自定，是日志和扩展存档数据的键，开发版与创意工坊版共用；重复的 `id` 只加载先出现的，另一个拒绝并写入启动报告。名称、版本等用 `descriptor.mod` 的。
- **接口版本**：0.x 阶段 `api_version` 必须与框架完全相同才加载；1.0 之后按语义化版本判断兼容。
- **生命周期**：不支持热重载；扩展加载后直到游戏进程结束都不卸载。
- **线程模型**：框架只在游戏主线程的安全时点调用扩展；回调期间产生的事件排队，当前回调返回后再派发；只有"投递到游戏线程"可从任意线程调用。
- **代码形态**：扩展实现 SDK 的一个 trait，每类事件一个方法（默认空实现）；事件方法收到"游戏"上下文，所有能力都是它的方法，出了回调就拿不到；唯一能带出回调、跨线程使用的是"投递器"。
- **出错处理**：在回调边界捕获 panic 和原生异常；之后不再调用该扩展（不卸载），隐藏它的界面元素，提示一次并写日志。
- **扩展之间**：不互相调用，也不声明依赖。同一事件的派发先后、按钮区里按钮的排列、同一时刻的着色请求，都按合集里的 Mod 顺序。

## 初版能力

- **会话**：是否在游戏中、玩家国家、当前日期、是否暂停。
- **事件**：每帧（暂停时也触发）、每日推进结束、读档完成、存档写入完成、回到主菜单、玩家手动给军队下令、军队战败。
- **国家**：标识；两国是否敌对。
- **省份**：所属国、控制者、相邻省份、对玩家是否可见。
- **军队**：所属国、所在省份、当前路线及其来源（玩家、本扩展、其他扩展、游戏）、状态（交战、围城、撤退、移动锁定）、对玩家是否可见。
- **寻路**：查询某支军队到某个省份的游戏原生路线。
- **命令**：让军队移动到某个省份；让军队停止。同步返回"已接受"或"被拒绝 + 原因"；接受不代表已到达。扩展自己的命令不触发"玩家手动下令"事件。
- **界面**：按钮（区分左右键）、提示文字、地图按省份着色及恢复，详见下节。
- **扩展存档数据**：每个扩展一份可序列化的数据，按存档身份（完整 SHA-256、存档路径、游戏日期）绑定，存在存档文件之外；身份对不上时为空（[ADR 0007](adr/0007-extension-save-data-outside-saves.md)）。
- **日志**：见"日志与诊断"。

游戏对象用游戏自己的稳定标识作为值：省份编号、国家标签、军队完整 64 位 ID。扩展可以长期保存；每次使用由框架重新查找，不在了就返回"不存在"。不暴露指针或只在回调内有效的句柄。读取一次取回一个对象的快照，另有列表查询（如本国全部军队、某省的相邻省份）。同一会话内的军队 ID 复用尚未验证。

## 界面

- **注入方式**：框架在游戏读取 `.gui` 文件时拼接文本，挂的是 eu4.exe 按名字导出的 PhysFS 函数；Mod 不覆盖原版 `.gui`（[ADR 0006](adr/0006-inject-ui-at-runtime.md)，依据见 [research/ui-injection.md](research/ui-injection.md)）。
- **目标窗口**：设计上可以是任何原版窗口，初版只验证和开放单支军队面板 `single_unitpanel`。
- **声明**：界面片段用 Paradox `.gui` 语法写在 Mod 自己的文件里，在清单 `ui` 字段声明片段文件和注入目标；放进按钮区的标 `"area": "buttons"`，其余片段的坐标相对于目标窗口。sprite 放在 Mod 自己新建的 `.gfx` 里。
- **命名**：注入元素在游戏里的名字自动加 `eu4harmony_<id>_` 前缀，扩展代码仍用原名；Mod 只需保证自身不重名。
- **按钮区**：贴在军队面板背景图（`regiment_bg`，516×450 固定图片）右侧外缘的竖条，带可拉伸的边框背景；按钮统一 48×48、间距 44 像素，超过 7 个换列。尺寸和坐标在拼接时按全部清单算好；运行中隐藏的按钮留空位，竖条不缩小。原版面板不改。
- **地图着色**：同一时刻只归一个扩展。新请求顶替旧的，被顶替者收到"着色被接管"事件；持有者释放后恢复原地图模式。
- **文字**：扩展通过 SDK 设置的文字一律传 UTF-8，由框架转成游戏需要的格式。检测到中文字体插件时按它的转义编码转换：常见中文标点换成对应英文标点，其他不支持的字符换成 `?` 并写日志；没有插件时原样传入。Mod 自己的本地化文件由作者按现有中文 Mod 的惯例编码。
- **提示**：扩展出错被停用、`id` 重复等情况，用框架自己的游戏内提示窗口显示，外观刻意与原版对话框不同，让玩家一眼看出是框架而不是游戏在说话。提示窗口拼进主菜单和游戏内顶栏这两个常驻原版窗口（[ADR 0008](adr/0008-notice-window-in-vanilla-hosts.md)）；主菜单出现前产生的提示先排队。exe 不认识时框架不挂游戏函数，游戏内显示失败时也一样，退回 Windows 消息框。每种情况每次会话最多提示一次。

## 开发者工具

- **SDK**：Rust crate，初版以本地路径依赖引用，不发布到 crates.io。提供日志宏。
- **假游戏**：SDK 附带内存里的假游戏，用于脱离 EU4 写扩展单元测试。只做数据仓库，不模拟游戏规则：测试直接摆放快照、指定寻路结果、手动触发事件；命令和界面操作只记录，不产生后果。
- **脚手架**：命令行工具 `eu4-harmony.exe`，只提供 Rust 模板。
  - `new <id>`：在当前目录生成 Mod：`descriptor.mod`、`eu4-harmony/manifest.json`、依赖 SDK 的 Rust 扩展工程（含示例事件处理和用假游戏写的测试）。
  - `build`：release 编译，把 DLL 复制到 `eu4-harmony/win64/`。
  - `link`：在用户目录 `mod/` 下写 `<id>.mod`，`path=` 指向开发目录，不复制；之后在启动器里手动勾选。不改 `dlc_load.json`。
  - `package`：生成干净的上传目录，只含 `descriptor.mod`、游戏资源和 `eu4-harmony/` 下的清单、界面片段与 DLL；上传用 Paradox 启动器自带的工具。

## 日志与诊断

- 框架为每个扩展写一个日志文件，另写框架日志和启动报告（找到哪些 Mod、各扩展是否加载及原因）。都放在用户目录的 `eu4-harmony/logs/`，每次启动覆盖，保留上一次的一份。
- 框架记录每个扩展每次回调的耗时，单次超过阈值（如 5 ms）写日志，启动报告附各扩展的耗时汇总。

## 初版不做

授权确认；多人模式识别（只声明仅支持单人）；热重载；扩展之间互相调用；特征码扫描；C 头文件和 C++ 模板；框架经创意工坊分发或更新；安装程序；Mod 本地化文件的编码转换；运行时重新排布按钮区；在游戏计算过程中拦截或改写结果的能力；`single_unitpanel` 以外的注入目标。

## 实现顺序

先做一个打通全链路的原型：`winmm.dll` 代理 → 发现 Mod → 拼接注入一个按钮 → 点击后写日志。用它实测以下问题，全部通过后再按本文铺开：

1. 代理加载时机，以及链式加载已有的 `winmm.dll`。
2. GUI 定义在哪个线程加载（主线程或 LoadingThread）；钩子线程安全。
3. 目标文件传给 `PHYSFS_openRead` 的路径格式；没有第二条读取路径或缓存。
4. 与覆盖同一 `.gui` 文件的 Mod 共存：拼接作用在胜出的文件上。
5. 拼接后的文本能被干净解析：按钮出现在面板中，`error.log` 无重名或语法错误。
6. 界面声明赶得上 `LOADING_GUI_DEF`。
7. `reload` / `reloadinterface` 之后拼接仍生效，绑定随面板重建正确重挂。
8. 与其他挂 PhysFS 的原生插件共存；挂钩前校验入口字节。
9. 框架放在 `eu4-harmony/` 里的界面资源（提示窗口的纹理等）能被游戏按相对游戏根目录的路径读到。
10. 拼进主菜单和顶栏的提示窗口能显示、关闭，宿主窗口重建后重新绑定。
