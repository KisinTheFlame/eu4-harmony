# The interface, text and input

What the player sees and touches: the windows with their buttons and text, the tooltips, the main menu, the map seen through the camera, the text in its fonts and the edit boxes it is typed into, the mouse and the keyboard, and the frame as it reaches the screen. The interface reads the game and changes it only through commands ([scripts.md](scripts.md)); it is drawn by the main thread in each frame, between the days ([day.md](day.md)).

## Windows

- **A window is made from its definition by name.** At startup the game reads every `.gfx` file (sprites and fonts), then every `.gui` file in `interface` into definitions (`windowType`, `guiButtonType`, `instantTextBoxType` and the rest), kept by name without regard to case; of two definitions with one name the first read wins, unless the game is set to let the later replace it. When a view needs its window, the game's interface manager builds it from the definition and its children ([research/ui-injection.md](../research/ui-injection.md), "The GUI loading path (verified)"; [research/architecture.md](../research/architecture.md), "Presentation"). A file is read whole into memory before it is parsed, which is where the framework adds its elements ([research/ui-injection.md](../research/ui-injection.md), "Mechanism 1: splicing text when the file is read — recommended").
- **A view is code with a window.** Each panel is a class of the game's that makes its window, finds the window's elements by name, subscribes to their buttons and sets them again every time it is updated: the single army panel holds its window and the army it shows, and sets its buttons and the mission settings' numbers at each update ([research/interface-bindings.md](../research/interface-bindings.md), "The army panel"; [research/architecture.md](../research/architecture.md), "Presentation").
- **Every window is of one kind.** A window finds a button, a text box or an icon among its own elements by name, not in the windows inside it, which it finds by name too; asked for a name it lacks it may hand back a stand-in of the kind asked for ([research/notice-window.md](../research/notice-window.md), "4. Lookups on other roots (verified)"; [research/interface-bindings.md](../research/interface-bindings.md), "Looking elements up").
- **Windows come and go with the game.** The top bar, the menu bar, the country view and the other in-game windows are built when a game's interface is set up, once a game; reloading one of their `.gui` files (`reload`) destroys and builds them again; returning to the main menu destroys them; an in-game load builds the top bar, the in-game menu and the load window again ([research/notice-window.md](../research/notice-window.md), "2.3 When it is rebuilt and when destroyed"; [research/main-menu.md](../research/main-menu.md), "Loading a save in a game").
- **Destroying a window only marks it.** Killing a window marks it and its elements dead, and they take no more input; the interface manager frees them in its sweep later in the same frame ([research/notice-window.md](../research/notice-window.md), "3. Destruction paths and where to hook").
- **Elements may lie outside their window.** Each is drawn and clicked by its own rectangle; nothing was found that clips it to its window ([research/notice-window.md](../research/notice-window.md), "5. Child elements outside the window's bounds").
- **The top bar slides out** in one map mode (the timeline's, inferred) and with the army reorganization window, its elements with it ([research/notice-window.md](../research/notice-window.md), "2.3 When it is rebuilt and when destroyed").

## Buttons, clicks and tooltips

- **A button has a click signal**, and whatever subscribes to it is called on a click; subscribing twice is called twice, and letting go while the signal is calling only marks the subscription ([research/interface-bindings.md](../research/interface-bindings.md), "The click signal").
- **A click is the release.** A left press followed by a release on the button makes a click; a button reports right clicks only once it is told to take them; a quick second left press is a double click, which goes to other subscribers' methods or nowhere, and the second of two quick right clicks is lost on every button. The army panel's own buttons take one click of a quick pair, as read from the code (it was not tried) ([research/interface-bindings.md](../research/interface-bindings.md), "From input to a click", "Callbacks").
- **A button keeps the click from the map**, whether anything subscribes to it or not ([research/interface-bindings.md](../research/interface-bindings.md), "From input to a click").
- **A tooltip is asked of the view** by the element's name, which fills its text for the elements it knows ([research/interface-bindings.md](../research/interface-bindings.md), "Tooltips"). Tooltips, like buttons and instant text boxes, are drawn into a texture of their own, which the window then shows ([research/font-textures.md](../research/font-textures.md), "Where glyphs land on pixels").
- **A text box owns its text** and frees it with the game's own allocator ([research/interface-bindings.md](../research/interface-bindings.md), "Text").
- **The army panel's rebel button** changes the army's mission and switches the map mode as it opens its window, so it is of no use for showing a range ([research/interface-bindings.md](../research/interface-bindings.md), "The rebel button's action"; [military.md](military.md), [provinces.md](provinces.md)).

## Input

- **From Windows to the game.** The game's window is SDL's: Windows' messages go to SDL's window procedure, which makes them into SDL's input; at the start of each frame the game reads it and hands it to whatever runs the screen, the main menu or the game ([research/input.md](../research/input.md), "From Windows to the game").
- **Who gets it first**: a modal window, then the interface's windows, then the map, the game itself, the camera, and last the hotkeys, the player's from `shortcuts.txt`; a handled input goes no further ([research/architecture.md](../research/architecture.md), "Presentation").
- **The game keeps no key state of its own**: what it knows of shift and control comes with each key, so a shift pressed in an earlier frame holds for a later click. The speed keys are the characters `+` and `-` ([research/input.md](../research/input.md), "From Windows to the game").
- **The cursor** is read once a frame: from Windows' cursor while the game is in front, from SDL's while another program is, until a button is pressed in the game ([research/input.md](../research/input.md), "Where the cursor is"). The cursor itself is Windows', not drawn into the frame (inferred) ([research/architecture.md](../research/architecture.md), "Presentation").

## Text and fonts

- **Game text is single bytes**, Windows-1252, with codes inside it: `§` and a letter for a color, `£` and a name for an icon, `@`, `$` and `¤` for the rest ([research/unicode-text.md](../research/unicode-text.md), "Fonts and glyphs").
- **A font is a bitmap font**: a page, a texture of glyphs, and up to 256 glyphs by byte, with kerning for those 256 only; a character it lacks is drawn as `?`; a `.fnt` line for a character above 255 is dropped ([research/unicode-text.md](../research/unicode-text.md), "Fonts and glyphs"). A font's `.gfx` block gives its name, its page and its color; fonts of different colors share a page, which is white and tinted as it is drawn ([research/font-textures.md](../research/font-textures.md), "How a font page loads", "A font's color").
- **The ways text is drawn** are the font's: main text, button text drawn into a texture of its own, text that floats up and fades, measured heights and widths, text fitted into a box (cut with `...`), and the names on the map, bent along a curve over the country ([research/unicode-text.md](../research/unicode-text.md), "The font's text methods"). Main text breaks lines at spaces only, so a word longer than a line is cut into full and short lines in turn ([research/unicode-text.md](../research/unicode-text.md), "Fonts and glyphs").
- **Drawn text is cached**: main text in 40 slots a font, by the text and where it is drawn; button text as finished pixels; the names on the map as meshes, built before a game starts ([research/font-textures.md](../research/font-textures.md), "Constraints from batches and caches").
- **The names on the map are drawn by the map's own shader**, `gfx/FX/mapname.shader`, the only user of its effect: it samples the font page with a linear filter and draws its colors as they are, so the closer the camera, the more each texel of the page is spread over the screen ([research/map-name-shader.md](../research/map-name-shader.md), "Why names blur when the map is close", "Who uses the mapname effect"). Shader files are read through the file system as script, built into one HLSL text each and compiled for Shader Model 3; the compiled shaders are cached by that whole text, so a changed file is compiled again ([research/map-name-shader.md](../research/map-name-shader.md), "How a shader file is read", "The shader cache").
- **The interface scale** stretches what is drawn: text is laid out in the interface's units and each unit shown as the scale's pixels, so a font's page is blurred above a scale of 1 ([research/font-textures.md](../research/font-textures.md), "The glyph scale").
- **A page of 16 MiB or more** is not loaded at all, without a word: the Chinese language mod's map font is 49 MB, so in vanilla the names on its map do not show ([research/font-textures.md](../research/font-textures.md), "The 16 MiB limit (tested)").
- **Language mods for Chinese, Japanese and Korean** write each character the game's single bytes lack as three bytes of their own ([research/unicode-text.md](../research/unicode-text.md), "Legacy escapes").

## Edit boxes and the input method

- **Typing** comes as SDL's text, of which the game takes only the first character: one of two bytes cut to one wrong byte, one of three bytes or more, as Chinese is, dropped; what the input method is still composing is dropped too ([research/text-input.md](../research/text-input.md), "1. From SDL's text event to the edit box").
- **An edit box works in bytes**: its caret, its left and right, Backspace and Delete, its length limit and its line wrapping, which breaks at spaces. Home and End select as they move; Shift and the arrows select nothing ([research/text-input.md](../research/text-input.md), "2. The edit box").
- **The clipboard** is UTF-8 on both sides, which the game's text is not ([research/text-input.md](../research/text-input.md), "2. The edit box").
- **The input method's windows** are hidden by SDL, and the game never says where the caret is; keys the input method takes still reach the game, so Enter that ends a composition also closes the box ([research/text-input.md](../research/text-input.md), "3. Input method").
- **A save's file name** is turned into plain ASCII: accented letters lose their accents, and every other byte above ASCII becomes `?`, every byte of a Chinese name among them ([research/text-input.md](../research/text-input.md), "4. Save file names").

## The main menu

- **The main menu is a set of pages** over the map: the first page, the single player setup, the multiplayer lobby and the rest ([research/main-menu.md](../research/main-menu.md), "The main menu object"; [research/architecture.md](../research/architecture.md), "Presentation").
- **Starting a game**: the single player setup selects a country by posting a command, and its start posts the start commands; the main menu then makes the game and switches to it. `-start_tag` on the command line skips to the setup with that country ([research/main-menu.md](../research/main-menu.md), "The single player setup (page 3)").
- **The continue box** loads its save and starts at one frame, so that the start runs after the load; a save loaded first and started later starts a new game instead ([research/main-menu.md](../research/main-menu.md), "The continue box", "The single player setup (page 3)").
- **The main menu is made once a process.** Every return to the main menu, and the setup's back button, ends the process and starts the game again ([research/main-menu.md](../research/main-menu.md), "Returning to the main menu", "The single player setup (page 3)"); what that leaves behind, and leaving a session without it, are in [program.md](program.md).

## The camera

- **Map positions** are pixels of the province map (`map/provinces.bmp`, 5632 by 2048), x across and up the map, as `map/positions.txt` writes them; a grid gives the province at every pixel ([research/camera.md](../research/camera.md), "Where the map is in the camera's world").
- **The camera glides.** It has where it is and where it looks, and where it is going to be; each frame it moves a little towards the goal. Looking at a province takes the province's own position on the map ([research/camera.md](../research/camera.md), "The camera", "Moving it").
- **It stays on the map**, between the heights the defines give (`CAMERA_MIN_HEIGHT` 50 and `CAMERA_MAX_HEIGHT` 3000) and above the ground; the map wraps from its right edge to its left; the game locks the camera now and then, and while it is locked nothing moves it ([research/camera.md](../research/camera.md), "The camera").

## The frame

- **A frame in a game**: input, the commands and time, the interface's update, then the drawing: the map mode's colors, the map with its names and its 3D scene, the sky, the interface, and Present ([research/architecture.md](../research/architecture.md), "Presentation"; [day.md](day.md)). The main menu's frame draws the same, without units and overlays.
- **Direct3D 9**: the game draws through a table of the renderer's functions, Direct3D 9 unless `-opengl` is given, on a device made for several threads ([research/architecture.md](../research/architecture.md), "Presentation"; [research/font-textures.md](../research/font-textures.md), "Threads").
- **What the player sees** is the back buffer just before Present, multisampled as `settings.txt` asks; while a save loads, another thread draws the loading screen ([research/screenshots.md](../research/screenshots.md), "The frame the player sees").

## What the framework relies on

- **Interface fragments** are spliced into `.gui` and `.gfx` files as the game reads them, and **bindings** find the added elements by name in the window's current instance, subscribe to their buttons and set them after the view's own update ([ADR inject-ui-at-runtime](../adr/2026-10-27-inject-ui-at-runtime.md); [research/ui-injection.md](../research/ui-injection.md), [research/interface-bindings.md](../research/interface-bindings.md)).
- **The framework UI** is drawn by the framework at Present, not in the game's windows ([ADR framework-draws-its-own-ui](../adr/2026-10-27-framework-draws-its-own-ui.md), which superseded [ADR notice-window-in-vanilla-hosts](../adr/2026-10-27-notice-window-in-vanilla-hosts.md)).
- **The Unicode module** takes over typing, the edit box, the input method, save names, the text methods and the fonts' pages, drawing game text in system fonts on pages that grow ([plans/unicode-module.md](../plans/unicode-module.md); [ADR built-in-unicode-module](../adr/2026-10-27-built-in-unicode-module.md), [ADR game-text-in-system-fonts](../adr/2026-11-02-game-text-in-system-fonts.md), [ADR font-pages-grow](../adr/2026-11-08-font-pages-grow.md)).
- **Input from remote clients** is handed to SDL's window procedure as Windows' own messages, with the cursor answered by the framework while input holds it ([plans/input.md](../plans/input.md); [ADR remote-clients-give-the-players-input](../adr/2026-11-04-remote-clients-give-the-players-input.md)).
- **The camera, screenshots and the main menu** as capabilities: looking at a province or a position, reading the frame back at Present, loading a save, starting as a country and returning ([plans/remote-control.md](../plans/remote-control.md); [research/camera.md](../research/camera.md), "What the framework relies on"; [research/screenshots.md](../research/screenshots.md)).
- **Repairs** of what the interface keeps: text boxes' animations, and the transparency masks of textures ([research/interface-bindings.md](../research/interface-bindings.md), "Text"; [research/font-textures.md](../research/font-textures.md), "Transparency masks"; [plans/leak-finding.md](../plans/leak-finding.md)).

## What is not known yet

- Whether anything clips elements to their window when drawing; whether a graphics device reset builds the windows again ([research/notice-window.md](../research/notice-window.md), "5. Child elements outside the window's bounds", "2.3 When it is rebuilt and when destroyed").
- A text box's own show and hide; how the game's button takes its input, past its base ([research/interface-bindings.md](../research/interface-bindings.md)). What the interface bindings note says was seen in the game was seen before this repository's test log began, and is not in it.
- Which texture each draw of text uses, and how glyphs on several pages are split into batches; what the map's second set of names shows ([research/unicode-text.md](../research/unicode-text.md), "Open questions"; [research/font-textures.md](../research/font-textures.md), "Constraints from batches and caches").
- Why `-continuelastsave` leaves the game at the main menu; where the game turns a player with no land to observing ([research/main-menu.md](../research/main-menu.md), "Startup", "Starting a game as a country").
